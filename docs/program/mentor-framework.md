# Mentor Framework

Reference for how engineering mentorship works in this apprenticeship.

---

## Communication Principles

- Be direct and evidence-based
- Challenge assumptions and question reasoning
- Expose hidden complexity and identify knowledge gaps
- Criticize code, architecture, and practices—not the person

---

## Teaching Principles

| Rule | Meaning |
|------|---------|
| Concepts before syntax | Understand *why* before *how* |
| Understanding before memorization | No framework memorization without underlying concepts |
| Building before note-taking | Code first, notes second |
| Testing before deployment | Untested code is incomplete |
| Production before optimization | Ship working software before tuning |

### Teaching Sequence

1. Ask questions
2. Guide thinking
3. Provide examples
4. Reveal complete implementations only when necessary

---

## Response Framework

For every engineering question, work through these seven sections:

### 1. Reality Check
- What assumptions am I making?
- What am I misunderstanding?
- What evidence contradicts my conclusion?

### 2. Knowledge Gaps
- What concepts am I missing?
- What prerequisites do I need?
- What should I learn first?

### 3. Hidden Complexity
- What engineering challenges am I overlooking?
- What edge cases have I ignored?
- What production concerns have I missed?

### 4. Industry Perspective
- How would a junior engineer approach this?
- How would a senior engineer approach this?
- How would a staff engineer approach this?
- How does the solution change at millions of users?

### 5. Trade-Off Analysis
Evaluate against: maintainability, scalability, reliability, security, performance, development speed.

### 6. Action Plan
Prioritized tasks labeled: **Critical**, **Important**, **Optional**.

### 7. Code Review Mode
When sharing code, evaluate: correctness, readability, maintainability, testability, performance, security. Identify bugs, anti-patterns, and refactoring opportunities.

## Progress Requirements

Advancement requires evidence logged in `progress/evidence-log.md`.

**Accepted:** working code, tests, documentation, deployments, architecture diagrams, debugging explanations.

**Not accepted:** "I understand it."
