# Lesson 30 — Common Array Errors

This is the **final lesson in Topic 5 — Arrays**.

You've learned how to create, access, traverse, search, and process arrays. Now we need to understand the mistakes that commonly cause array programs to fail.

---

## 1. `ArrayIndexOutOfBoundsException`

Consider:

```java
int[] numbers = {10, 20, 30};
```

There are 3 elements:

```text
Index:   0    1    2
Value:  10   20   30
```

The valid indexes are:

```text
0, 1, 2
```

This is invalid:

```java
System.out.println(numbers[3]);
```

Because index `3` doesn't exist.

Java will throw:

```text
ArrayIndexOutOfBoundsException
```

### Remember

```text
length = 3
last index = 2
```

So:

> **Last index = array.length - 1**

---

# 2. The Off-by-One Error

This is one of the most common array mistakes.

Correct:

```java
for (int i = 0; i < numbers.length; i++) {
    System.out.println(numbers[i]);
}
```

Incorrect:

```java
for (int i = 0; i <= numbers.length; i++) {
    System.out.println(numbers[i]);
}
```

Why?

Suppose:

```text
numbers.length = 5
```

The correct loop visits:

```text
0
1
2
3
4
```

The incorrect loop eventually reaches:

```text
5
```

But index `5` doesn't exist.

### Mental rule

When traversing an array:

```java
i < array.length
```

not:

```java
i <= array.length
```

---

# 3. Confusing Length With Last Index

This distinction is extremely important.

Suppose:

```java
int[] numbers = {10, 20, 30, 40, 50};
```

Then:

```text
numbers.length = 5
```

But:

```text
last index = 4
```

Because:

```text
length - 1
5 - 1
4
```

So:

```java
numbers.length
```

means:

> "How many elements are there?"

while:

```java
numbers[4]
```

means:

> "Give me the element at index 4."

These are **not the same thing**.

---

# 4. Accessing an Array That Wasn't Created

Look at this:

```java
int[] numbers;
```

We've only **declared** the variable.

We haven't created an array yet.

If we try:

```java
System.out.println(numbers[0]);
```

Java won't have an actual array to access.

You need to create it first:

```java
int[] numbers = new int[5];
```

Now the array exists.

---

# 5. `NullPointerException`

Here's another situation:

```java
int[] numbers = null;
```

`numbers` doesn't refer to an actual array.

Then:

```java
System.out.println(numbers.length);
```

or:

```java
System.out.println(numbers[0]);
```

will cause a:

```text
NullPointerException
```

For now, remember the basic idea:

> `null` means the variable isn't referring to an actual object/array.

---

# 6. Trying to Add to a Fixed-Size Array

Suppose:

```java
int[] numbers = {10, 20, 30};
```

You might think:

```java
numbers[3] = 40;
```

would add `40`.

It doesn't.

There is no index `3`.

The array has already been created with 3 elements.

You **can replace** an existing value:

```java
numbers[2] = 40;
```

Now:

```text
10
20
40
```

But you cannot make the existing array larger.

This is one of the fundamental characteristics of Java arrays:

> **Arrays have a fixed size after creation.**

---

# 7. Review: The Array Rules

You should now be able to recognize these rules:

### Rule 1 — Index starts at zero

```text
First element → index 0
```

### Rule 2 — Last index

```text
array.length - 1
```

### Rule 3 — Valid traversal

```java
for (int i = 0; i < array.length; i++)
```

### Rule 4 — Arrays have fixed size

Once created:

```java
new int[5]
```

the array has exactly 5 elements.

### Rule 5 — Declaration isn't creation

```java
int[] numbers;           // declaration
numbers = new int[5];    // creation
```

### Rule 6 — `null` isn't an array

```java
int[] numbers = null;
```

The variable exists, but it doesn't reference an actual array.
