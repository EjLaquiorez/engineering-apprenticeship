# Lesson 02 — Variable Scope

## Objective

By the end of this lesson, you should understand:

* What **scope** means.
* Where a variable can be accessed.
* Why variables declared inside a block cannot be accessed outside it.
* How `{ }` creates boundaries for local variables.
* Why scope is important for writing maintainable programs.

---

# 1. The Problem

Consider:

```java
public class Lesson02 {

    public static void main(String[] args) {

        int age = 25;

        System.out.println(age);
    }
}
```

Where can `age` be used?

Inside `main`:

```java
System.out.println(age);
```

✅ Works.

But what about outside `main`?

```java
public class Lesson02 {

    public static void main(String[] args) {

        int age = 25;
    }

    public static void test() {

        System.out.println(age);
    }
}
```

This doesn't work.

Why?

Because `age` only exists within a particular **scope**.

---

# 2. What Is Scope?

**Scope is the region of a program where a variable can be accessed.**

For example:

```java
public static void main(String[] args) {

    int age = 25;

    System.out.println(age);
}
```

Think of the braces as a boundary:

```text
main()
{
    ┌─────────────────────┐
    │                     │
    │ int age = 25;       │
    │                     │
    │ System.out.println  │
    │ (age);              │
    │                     │
    └─────────────────────┘
}
```

`age` is available inside that boundary.

---

# 3. Block Scope

Java uses `{ }` to define blocks.

For example:

```java
if (true) {

    int score = 100;

    System.out.println(score);
}
```

`score` exists inside the `if` block.

But this:

```java
if (true) {

    int score = 100;
}

System.out.println(score);
```

❌ Does not compile.

Why?

Because `score` was declared inside the `if` block.

Its scope ended when the closing `}` was reached.

```text
if (true) {
    │
    │  score exists here
    │
} ← scope ends here

score no longer accessible
```

---

# 4. Scope Is About Accessibility

This distinction is important.

When a variable goes out of scope, don't think:

> "The variable has been deleted immediately."

Instead, think:

> **The variable is no longer accessible from that location in the program.**

For now, focus on **where the variable can legally be referenced**.

---

# 5. Scope Can Be Nested

Consider:

```java
public static void main(String[] args) {

    int age = 25;

    if (age >= 18) {

        int licenseNumber = 12345;

        System.out.println(age);
        System.out.println(licenseNumber);
    }

    System.out.println(age);
}
```

Notice something interesting.

Inside the `if` block:

```java
System.out.println(age);
```

works.

Why?

Because the `if` block is **inside** the scope of `main`.

So:

```text
main scope
┌──────────────────────────────┐
│                              │
│ age                          │
│                              │
│   if scope                   │
│   ┌──────────────────────┐   │
│   │                      │   │
│   │ licenseNumber        │   │
│   │                      │   │
│   │ age is also visible  │   │
│   │                      │   │
│   └──────────────────────┘   │
│                              │
└──────────────────────────────┘
```

The inner scope can access variables from the outer scope.

But the reverse isn't true.

---

# 6. Outer Scope Cannot See Inner Variables

This is one of the most important rules.

```java
int age = 25;

if (age >= 18) {

    int licenseNumber = 12345;
}

System.out.println(age);            // ✅
System.out.println(licenseNumber);  // ❌
```

Why?

Because:

```text
age
↓
declared in outer scope
↓
visible to inner scope
```

But:

```text
licenseNumber
↓
declared in inner scope
↓
NOT visible to outer scope
```

Think of scope like rooms:

```text
Outside room
┌─────────────────────────────┐
│                             │
│ age                         │
│                             │
│    Inside room              │
│    ┌────────────────────┐   │
│    │ licenseNumber      │   │
│    │                    │   │
│    └────────────────────┘   │
│                             │
└─────────────────────────────┘
```

Someone inside the inner room can see the outer room.

Someone outside cannot see what's inside the closed inner room.

---

# 7. Method Scope

This becomes particularly important with methods.

Consider:

```java
public class Lesson02 {

    public static void main(String[] args) {

        int age = 25;

        System.out.println(age);
    }

    public static void printSomething() {

        System.out.println(age);
    }
}
```

❌ `printSomething()` cannot access `age`.

Why?

Because `age` belongs to the scope of `main`.

`printSomething()` has its own scope.

```text
main()
┌─────────────────┐
│ age             │
└─────────────────┘

printSomething()
┌─────────────────┐
│                 │
│ age unavailable │
└─────────────────┘
```

This will become extremely important when we study **methods** later.

---

# 8. Variables With the Same Name

Here's another important situation.

```java
int score = 50;

if (true) {

    int score = 100;
}
```

You might think:

> "There are two variables called `score`."

But Java does **not** allow you to redeclare a local variable with the same name in an overlapping local scope like this.

So this is a compilation error.

However, nested scopes and later examples will introduce more nuanced cases. For now:

> **Don't declare another local variable with the same name when the original variable is already in scope.**

---

# 9. Why Scope Exists

Scope isn't just a Java rule designed to annoy programmers.

It provides **control over program complexity**.

Imagine a large application where every variable could be accessed from everywhere.

You could have:

```text
customerName
customerAge
orderTotal
paymentStatus
databaseConnection
temporaryValue
counter
...
```

all accessible from arbitrary parts of the program.

That would make it difficult to determine:

* Who changed a value?
* Where was it changed?
* Which code depends on it?
* Can I safely rename it?
* Can I safely modify it?

Scope limits access.

That makes programs easier to reason about.

---

# 10. A Practical Example

Consider:

```java
public static void main(String[] args) {

    int price = 100;

    if (price > 50) {

        int discount = 10;

        price = price - discount;
    }

    System.out.println(price);
}
```

After execution:

```text
price → 90
```

But:

```text
discount
```

is only needed inside the `if` block.

So putting it inside that block limits its scope.

That's good design.

Instead of:

```java
int discount = 10;
```

existing throughout the entire method, we keep it close to where it's actually needed.

---

# 11. Engineering Principle

A useful rule:

> **Keep variables in the smallest scope that makes sense.**

Bad habit:

```java
int temporaryCalculation = 0;

// hundreds of lines of code

// finally use it
```

Better:

```java
if (condition) {

    int temporaryCalculation = 10;

    // use it here
}
```

Smaller scope means fewer places can accidentally interact with the variable.

This becomes increasingly important as our programs grow.
