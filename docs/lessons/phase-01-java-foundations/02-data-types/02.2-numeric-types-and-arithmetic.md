# Lesson 04 — Numeric Types and Arithmetic

## Objective

By the end of this lesson, you should be able to:

* Perform arithmetic with Java's numeric types.
* Understand `+`, `-`, `*`, `/`, and `%`.
* Explain integer division.
* Understand how the types of operands affect the result.
* Recognize basic integer overflow.
* Use parentheses to control calculation order.

The important goal is not memorizing operators.

It's understanding **what Java actually calculates**.

---

# 1. Basic Arithmetic

Java supports the standard arithmetic operators:

```text
+    addition
-    subtraction
*    multiplication
/    division
%    remainder
```

Example:

```java
int a = 10;
int b = 3;

System.out.println(a + b);
System.out.println(a - b);
System.out.println(a * b);
System.out.println(a / b);
System.out.println(a % b);
```

What do you expect?

Let's focus on `/` and `%`.

---

# 2. Addition

```java
int a = 10;
int b = 3;

int result = a + b;
```

Result:

```text
13
```

Simple:

```text
10 + 3 = 13
```

---

# 3. Subtraction

```java
int result = 10 - 3;
```

Result:

```text
7
```

---

# 4. Multiplication

```java
int result = 10 * 3;
```

Result:

```text
30
```

---

# 5. Division — The Important One

Now:

```java
int result = 10 / 3;
```

What do you think `result` is?

You might expect:

```text
3.333333...
```

But it isn't.

The result is:

```text
3
```

Why?

Because **both operands are integers**:

```text
10 → int
3  → int
```

Therefore Java performs **integer division**.

The fractional part is discarded.

```text
10 / 3

10 ÷ 3

3 remainder 1

result → 3
```

It does not round.

For example:

```java
int a = 7 / 2;
```

produces:

```text
3
```

Not:

```text
3.5
```

And:

```java
int a = 9 / 4;
```

produces:

```text
2
```

Not:

```text
2.25
```

---

# 6. Getting the Decimal Result

If you want floating-point division, at least one operand needs to be floating-point.

For example:

```java
double result = 10.0 / 3.0;
```

Result:

```text
3.3333333333333335
```

Or:

```java
double result = 10 / 3.0;
```

Because one operand is `double`, Java performs floating-point division.

```text
10     → int
3.0    → double
          ↓
       double result
```

Result:

```text
3.3333333333333335
```

This is an example of **numeric promotion**, which we'll examine more closely later.

---

# 7. The `%` Operator

The `%` operator gives you the **remainder** after integer division.

Example:

```java
int result = 10 % 3;
```

Think:

```text
10 ÷ 3

3 × 3 = 9

10 - 9 = 1
```

Therefore:

```text
10 % 3 = 1
```

Another example:

```java
int result = 20 % 5;
```

Since:

```text
20 ÷ 5 = 4
```

there is no remainder.

Therefore:

```text
20 % 5 = 0
```

---

# 8. Why `%` Is Useful

The remainder operator is extremely useful in programming.

For example, checking whether a number is even:

```java
int number = 10;

System.out.println(number % 2);
```

Result:

```text
0
```

Therefore:

```java
if (number % 2 == 0) {
    System.out.println("Even");
}
```

We'll use this kind of logic heavily when we reach **control flow**.

# 9. Arithmetic With Variables

We don't have to perform calculations directly on literals.

```java
int price = 100;
int quantity = 3;

int total = price * quantity;

System.out.println(total);
```

Result:

```text
300
```

Conceptually:

```text
price     → 100
quantity  → 3

       ↓

100 × 3

       ↓

total → 300
```

This is where variables become useful.

---

# 10. Combining Operations

Consider:

```java
int result = 10 + 5 * 2;
```

What is the answer?

Not:

```text
30
```

It is:

```text
20
```

Why?

Java follows normal operator precedence.

Multiplication happens before addition:

```text
5 × 2 = 10

10 + 10 = 20
```

---

# 11. Parentheses

You can explicitly control the order:

```java
int result = (10 + 5) * 2;
```

Now:

```text
10 + 5 = 15

15 × 2 = 30
```

Result:

```text
30
```

Compare:

```java
10 + 5 * 2
```

with:

```java
(10 + 5) * 2
```

```text
10 + 5 * 2      → 20

(10 + 5) * 2    → 30
```

### Engineering habit

When an expression becomes difficult to understand, **use parentheses to make your intent obvious**.

Don't rely on the reader remembering precedence rules.

---

# 12. Integer Overflow

Remember that `int` has a limited range:

```text
-2,147,483,648
to
 2,147,483,647
```

What happens here?

```java
int number = 2_147_483_647;

number = number + 1;

System.out.println(number);
```

You might expect:

```text
2147483648
```

But that value is outside the range of `int`.

Java's integer arithmetic wraps around.

The result becomes:

```text
-2147483648
```

This is called **integer overflow**.

The same general idea applies to other fixed-width integer types.

---

# 13. Numeric Separators

Java allows underscores inside numeric literals to make large numbers easier to read:

```java
int population = 1_000_000;
long distance = 9_000_000_000L;
```

These mean exactly the same as:

```java
1000000
9000000000L
```

The underscores are for humans.

They don't change the numeric value.

---

# 14. Negative Numbers

Arithmetic also works with negative values:

```java
int balance = -500;
int payment = 200;

int remaining = balance + payment;
```

Result:

```text
-300
```

You can also calculate:

```java
int result = -10 + 5;
```

Result:

```text
-5
```

---

# 15. A Critical Difference

Compare:

```java
int result = 10 / 4;
```

and:

```java
double result = 10.0 / 4;
```

First:

```text
10 / 4
↓
integer division
↓
2
```

Second:

```text
10.0 / 4
↓
floating-point division
↓
2.5
```

The **type of the operands affects the operation**.

That's a major concept.
