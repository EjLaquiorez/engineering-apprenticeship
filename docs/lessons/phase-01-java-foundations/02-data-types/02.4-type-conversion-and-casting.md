# Lesson 06 — Type Conversion

## Objective

By the end of this lesson, you should understand:

* What type conversion means.
* The difference between **widening** and **narrowing** conversion.
* Why some conversions happen automatically.
* Why other conversions require an explicit **cast**.
* How narrowing conversion can cause data loss.
* How Java converts numeric values between primitive types.

---

# 1. Why Do We Need Type Conversion?

Suppose we have:

```java
int number = 10;
```

Now we want to put that value into a `double`:

```java
double value = number;
```

This works.

Why?

Because Java knows that an `int` can be safely represented as a `double` in this context.

Conceptually:

```text
int
  ↓
double
```

This is called **widening conversion**.

---

# 2. Widening Conversion

Widening means converting from a type with a smaller range/representation to one that can accommodate it without narrowing the numeric range.

For example:

```java
int number = 10;
double value = number;

System.out.println(value);
```

Output:

```text
10.0
```

Notice:

```text
10
 ↓
10.0
```

The value is represented as a `double`.

Java performs this conversion automatically.

This is sometimes called an **implicit conversion**.

---

# 3. Another Example

```java
int age = 25;
double exactAge = age;
```

Java effectively performs:

```text
25
 ↓
25.0
```

You don't need to write:

```java
double exactAge = (double) age;
```

Although you *can* explicitly cast it:

```java
double exactAge = (double) age;
```

The cast isn't necessary here.

---

# 4. Common Widening Direction

For integer types, a useful simplified progression is:

```text
byte
 ↓
short
 ↓
int
 ↓
long
 ↓
float
 ↓
double
```

And:

```text
char
```

can also participate in numeric conversions.

However, don't interpret this as meaning every conversion in this diagram is equally safe in terms of exact numeric precision. In particular, `long → float` and `long → double` can lose integer precision for sufficiently large values.

For the beginner-level rule:

> **Widening conversions generally move toward types capable of representing a broader numeric range, and Java can often perform them automatically.**

---

# 5. Narrowing Conversion

Now reverse the situation.

Suppose:

```java
double number = 10.5;
```

and we want:

```java
int value = number;
```

Java rejects this.

Why?

Because `double` can contain fractional values:

```text
10.5
```

while `int` cannot.

Java does **not** automatically throw away the `.5`.

You must explicitly tell Java:

> "I understand that this conversion may lose information."

That's called a **cast**.

---

# 6. Casting

The syntax is:

```java
(type) value
```

For example:

```java
double number = 10.5;

int value = (int) number;

System.out.println(value);
```

Output:

```text
10
```

The cast:

```java
(int)
```

tells Java to convert the value to `int`.

The fractional portion is discarded.

```text
10.5
 ↓
(int)
 ↓
10
```

This is **narrowing conversion**.

---

# 7. Casting Does Not Round

This is important.

Consider:

```java
double number = 10.9;

int value = (int) number;
```

The result is:

```text
10
```

Not:

```text
11
```

Java doesn't round the value during this cast.

It **truncates toward zero**.

Examples:

```java
(int) 10.9   → 10
(int) 10.1   → 10
(int) -10.9  → -10
```

---

# 8. Data Loss

This is why narrowing conversion needs to be explicit.

Consider:

```java
double price = 1499.99;

int wholePrice = (int) price;
```

You get:

```text
1499
```

The `.99` is gone.

Therefore:

```text
double
1499.99
   ↓
  cast
   ↓
int
1499
```

Information was lost.

Java makes you explicitly request this potentially lossy operation.

---

# 9. Widening vs Narrowing

Compare these:

### Widening

```java
int number = 25;
double value = number;
```

```text
25
 ↓
25.0
```

✅ Automatic.

### Narrowing

```java
double number = 25.75;
int value = (int) number;
```

```text
25.75
 ↓
25
```

⚠️ Explicit cast required.

---

# 10. `char` and Numeric Conversion

Remember that `char` has an integral numeric representation.

For example:

```java
char letter = 'A';

int number = letter;

System.out.println(number);
```

Output:

```text
65
```

This is a widening conversion:

```text
char
 ↓
int
```

Going back:

```java
int number = 65;

char letter = (char) number;

System.out.println(letter);
```

Output:

```text
A
```

Here we're explicitly converting:

```text
int
 ↓
char
```

---

# 11. A Very Important Example

Look carefully at:

```java
int a = 10;
double b = 3;

double result = a / b;
```

What happens?

You might remember:

```text
10 / 3
```

with two `int`s gives:

```text
3
```

But here:

```text
a → int
b → double
```

So Java performs the calculation as floating-point division.

Result:

```text
3.3333333333333335
```

The conversion happens as part of the expression.

Conceptually:

```text
10      → int
3       → double
          ↓
10 converted/promoted for the operation
          ↓
10.0 / 3.0
          ↓
3.333...
```

---

# 12. Don't Confuse Assignment With Casting

These are different concepts.

### Assignment

```java
int age = 25;
```

You're assigning a value to a variable.

### Casting

```java
double price = 19.99;
int wholePrice = (int) price;
```

You're explicitly requesting a type conversion.

So:

```text
assignment
↓
put a value into a variable

casting
↓
explicitly convert a value to another type
```

---

# 13. Casting Can Also Change the Result of an Expression

Compare:

```java
int result = (int) 10.9;
```

with:

```java
double result = 10 / 3;
```

The first explicitly converts:

```text
10.9 → 10
```

The second performs integer division first:

```text
10 / 3 → 3
```

Then assigns `3` to a `double`:

```text
3 → 3.0
```

So:

```java
double result = 10 / 3;
```

produces:

```text
3.0
```

**not**:

```text
3.333...
```

This is a very common beginner mistake.

If you want decimal division:

```java
double result = 10.0 / 3;
```

---

# 14. Integer Division vs Casting

Consider:

```java
double result = (double) 10 / 3;
```

The cast changes the first operand:

```text
(int) 10
    ↓
(double) 10
```

So the operation becomes effectively:

```text
10.0 / 3
```

Result:

```text
3.3333333333333335
```

This is different from:

```java
double result = (double) (10 / 3);
```

Here:

```text
10 / 3
 ↓
3
 ↓
3.0
```

Result:

```text
3.0
```

### This distinction is extremely important.

```text
(double) 10 / 3
       ↓
conversion BEFORE division
       ↓
3.333...

(double) (10 / 3)
          ↓
division BEFORE conversion
          ↓
3.0
```

Parentheses can completely change the result.
