---

# 1. What Is `void`?

Look at this method:

```java
static void displayWelcome() {
    System.out.println("Welcome!");
}
```

The `void` means:

> **This method does not return a value.**

Compare it with your previous method:

```java
static double calculateSubTotal(double price, int quantity) {
    return price * quantity;
}
```

Here:

```text
double
  ↓
method returns a double
```

But:

```java
static void displayWelcome()
```

means:

```text
void
  ↓
method returns nothing
```

---

# 2. `void` Does NOT Mean "Does Nothing"

This is an important distinction.

A `void` method can perform an action.

For example:

```java
static void displayMenu() {
    System.out.println("1. Start");
    System.out.println("2. Exit");
}
```

It clearly does something.

It prints the menu.

It simply **doesn't give a value back to the caller**.

Think:

```text
void method

caller
  ↓
method
  ↓
performs action
  ↓
finished
```

Whereas a returning method:

```text
caller
  ↓
method
  ↓
calculates
  ↓
returns value
  ↓
caller receives value
```

---

# 3. `void` vs Return Value

Let's put them side by side.

### `void`

```java
static void displayName(String name) {
    System.out.println("Name: " + name);
}
```

Call:

```java
displayName("Justine");
```

The method prints:

```text
Name: Justine
```

But you cannot do:

```java
String name = displayName("Justine");
```

because `displayName()` doesn't return a `String`.

---

### Returning `String`

```java
static String getName() {
    return "Justine";
}
```

Now:

```java
String name = getName();
```

works because:

```text
getName()
   ↓
returns String
   ↓
String name receives it
```

---

# 4. Ask Yourself: "Does the Caller Need a Value?"

This is one of the most useful ways to decide between `void` and a return type.

Suppose we need to display a welcome message:

```java
static void displayWelcome() {
    System.out.println("Welcome!");
}
```

Does the caller need a value?

**No.**

The method's job is simply to perform an action.

So:

```text
void ✅
```

Now suppose we need to calculate a total:

```java
static double calculateTotal(double price, int quantity) {
    return price * quantity;
}
```

Does the caller need the calculated total?

**Yes.**

So:

```text
double ✅
```

---

# 5. Another Example

Imagine a program needs to check whether someone is an adult.

We could write:

```java
static boolean isAdult(int age) {
    return age >= 18;
}
```

Why isn't this `void`?

Because the caller needs the answer:

```text
true or false
```

For example:

```java
boolean result = isAdult(27);
```

Now `result` contains:

```text
true
```

But displaying a message doesn't need to return anything:

```java
static void displayAdultMessage() {
    System.out.println("You are an adult.");
}
```

---

# 6. `void` Methods Can Have Parameters

`void` does **not** mean the method can't receive information.

You already did this in Lesson 19:

```java
static void displayStudent(String name, int age, char grade) {
    System.out.println("Name: " + name);
    System.out.println("Age: " + age);
    System.out.println("Grade: " + grade);
}
```

It has:

```text
Parameters → YES
Return value → NO
```

So:

```text
void
```

only describes the **output**, not the input.

This is a very important distinction.

```text
              METHOD

       INPUT              OUTPUT
         ↓                   ↓
   parameters            return type

String name             void
int age
char grade
```

---

# 7. Can a `void` Method Use `return`?

This is where things get interesting.

A `void` method cannot return a value:

```java
static void test() {
    return 10;    // ❌
}
```

because `void` means:

> No value is returned.

However, a `void` method **can** use:

```java
return;
```

by itself.

For example:

```java
static void checkAge(int age) {

    if (age < 18) {
        return;
    }

    System.out.println("Adult");
}
```

Here:

```java
return;
```

means:

> Stop executing this method and leave.

It does **not** return a value.

We'll encounter this pattern more when we work with control flow inside methods.

---

# 8. A Simple Mental Model

Think of methods as machines.

### `void` method

```text
        INPUT
          ↓
    ┌───────────┐
    │   METHOD  │
    └───────────┘
          ↓
       ACTION
```

Nothing comes back.

### Returning method

```text
        INPUT
          ↓
    ┌───────────┐
    │   METHOD  │
    └───────────┘
          ↓
      RESULT
          ↓
       CALLER
```

Something comes back.
