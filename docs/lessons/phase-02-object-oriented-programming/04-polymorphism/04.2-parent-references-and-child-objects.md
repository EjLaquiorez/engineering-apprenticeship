# 1. Parent Reference vs. Child Object

Look at this:

```java
Animal animal = new Dog();
```

There are **two different types** involved:

```text
Animal animal = new Dog();
   ↑      ↑         ↑
reference variable object
  type
```

So:

* `Animal` → reference type
* `animal` → reference variable
* `Dog` → actual object type

You already learned this in Lesson 22. Now we're going to understand **what the reference controls**.

---

# 2. What Can the Reference Access?

Suppose we have:

```java
class Animal {

    public void eat() {
        System.out.println("Animal is eating");
    }
}
```

And:

```java
class Dog extends Animal {

    public void bark() {
        System.out.println("Dog is barking");
    }
}
```

Now:

```java
Animal animal = new Dog();
```

Can we do this?

```java
animal.eat();
```

**Yes.** ✅

Why?

Because `eat()` belongs to `Animal`, which is the reference type.

But what about:

```java
animal.bark();
```

❌ **This does not compile.**

Even though the actual object is a `Dog`.

### 🧠 Important rule

> **The reference type determines what methods you are allowed to access at compile time.**

So:

```java
Animal animal = new Dog();
```

The compiler looks at `Animal` when deciding what you can call.

---

# 3. But the Object Is Still a Dog

This is the interesting part.

Even though:

```java
Animal animal = new Dog();
```

the object itself is still a:

```text
Dog
```

The reference being `Animal` does **not** change the object into an `Animal`.

Think of it like this:

```text
Animal reference
       |
       ↓
   ┌─────────┐
   │ Dog     │
   │ object  │
   └─────────┘
```

The `Dog` object still exists as a `Dog`.

This distinction becomes extremely important in **Lesson 24 — Runtime Method Dispatch**.

---

# 4. Upcasting

When we do:

```java
Animal animal = new Dog();
```

we are performing **upcasting**.

Why?

Because we're treating a more specific type:

```text
Dog
```

as a more general type:

```text
Animal
```

Since:

```java
Dog extends Animal
```

Java allows:

```java
Animal animal = new Dog();
```

without explicitly casting.

### Think of it as:

```text
Specific
   ↓
  Dog
   ↓
 Animal
General
```

A `Dog` **is an** `Animal`, so Java can safely treat the Dog as an Animal.

### Remember this distinction

| What determines it?        | Rule                                            |
| -------------------------- | ----------------------------------------------- |
| Reference type (`Animal`)  | Which methods you can access at compile time    |
| Actual object type (`Dog`) | Which overridden implementation runs at runtime |
