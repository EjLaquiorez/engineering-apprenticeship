Today's goal: Learn how to design code so that adding a new child class doesn't require modifying a long chain of `if/else` statements.

## 1. The problem: too many conditions

Imagine you're building a notification system. Your program can send email, SMS, or push notifications.

A beginner might write something like this:

```
if (type.equals("email")) {
    System.out.println("Sending email...");
} else if (type.equals("sms")) {
    System.out.println("Sending SMS...");
} else if (type.equals("push")) {
    System.out.println("Sending push notification...");
}
```

This code works for three types. But imagine adding WhatsApp, in-app notifications, and five more notification types. You would keep modifying the same conditional logic.

That can make code harder to maintain and test.

## 2. Let polymorphism handle the differences

Instead, we can create a common parent type with a shared method.

Notification

`send()`

EmailNotification

Sends email

SMSNotification

Sends SMS

PushNotification

Sends push

Each child class overrides `send()` with its own behavior.

The code that processes notifications can then call:

```
notification.send();
```

It doesn't need to ask which notification type it received. Runtime method dispatch chooses the correct implementation.

### The design principle

Put shared behavior behind a common type, and let each child implement its own specific behavior.

This is useful because you can add another notification class without adding another condition to the code that processes notifications.

However, polymorphism isn't automatically better in every situation. For a tiny, fixed set of simple choices, an `if/else` statement may be perfectly reasonable. Design should solve a real problem, not add complexity unnecessarily.

## 3. Exercise 26A — Replace Conditionals

Let's practice with a simpler example before tackling notifications.

Imagine this existing code:

```
String animalType = "dog";

if (animalType.equals("dog")) {
    System.out.println("Dog barks.");
} else if (animalType.equals("cat")) {
    System.out.println("Cat meows.");
}
```

Your goal is to redesign it using inheritance and polymorphism rather than checking a string repeatedly.
