## 1. The problem: different objects, repeated code

Imagine you have three animals:

Java

```
Dog dog = new Dog();
Cat cat = new Cat();
Dog anotherDog = new Dog();
```

You want each animal to make its sound.

You could call each object's method individually. But what if you had 100 animals? Writing each call separately would become tedious.

Polymorphism gives us a better approach.

## 2. Use a parent-type array

Because both `Dog` and `Cat` extend `Animal`, Java allows us to create an `Animal` array containing both types.

`Animal[] animals`

One array with a common parent type

`Dog`

Element 0

`Cat`

Element 1

`Dog`

Element 2

Here is the Java syntax:

Java

```
Animal[] animals = {
    new Dog(),
    new Cat(),
    new Dog()
};
```

Notice the important difference: the array's element type is `Animal`, but the objects stored inside it can be `Dog` or `Cat`.

This works because both child classes are also `Animal` objects.

## 3. Process the array with a loop

Assume `Animal` defines `makeSound()`, and `Dog` and `Cat` override it.

You can process every element with an enhanced `for` loop:

Java

```
for (Animal animal : animals) {
    animal.makeSound();
}
```

Expected output:

```
Woof!
Meow!
Woof!
```

Here's how to read the loop:

* `Animal` — the type of reference used for each element.

* `animal` — a temporary reference to the current element.

* `animals` — the array being traversed.

* `animal.makeSound()` — calls the appropriate overridden method for that element's actual object type.

The loop doesn't need to know whether each element is a `Dog` or a `Cat`. Runtime method dispatch handles that.

### Why this matters

Without polymorphism, you might write separate code for dogs and cats. With polymorphism, you can use one common type and one loop to process them.

This makes code easier to extend. For example, you could add a `Bird` class that extends `Animal` and overrides `makeSound()` without changing the loop.
