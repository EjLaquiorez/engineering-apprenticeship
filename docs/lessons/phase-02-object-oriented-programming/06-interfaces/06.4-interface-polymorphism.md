Correct! ✅ Answer B — Runtime method dispatch.

Your explanation is accurate. Java uses the actual object's class at runtime to determine which overridden method to execute.

In your example:

```
Describable item = new Book();
item.describe(); // Calls Book.describe()

item = new Magazine();
item.describe(); // Calls Magazine.describe()
```

The reference's declared type remains `Describable`, but the object it points to changes. Java selects the appropriate implementation automatically.

Remember: The reference type determines which methods you can access at compile time; the actual object's class determines which overridden implementation runs at runtime.

## 1. Code review

Your key method is:

```
public static void processItems(Describable[] items) {
    for (Describable item : items) {
        item.describe();
    }
}
```

Here's why this is good design:

- Accepts the interface type: The method doesn't depend on `Book`, `Magazine`, or `LibraryReport` specifically.
- Uses polymorphism: Each object's own `describe()` implementation runs.
- Avoids duplication: One method handles all three types.
- Supports extension: If you add another class implementing `Describable`, this method can process it without modification.

Your `main()` is also correct:

```
Describable[] items = {new Book(), new Magazine(), new LibraryReport()};
processItems(items);
```

Expected output:

```
Book: Clean Code
Magazine: National Geographic
Report: Monthly Library Summary
```

One minor style note: Java convention generally uses `public static` for public methods, as you did. The method does not need to be `public` for this particular example because everything is inside one class, but keeping it public is valid.
