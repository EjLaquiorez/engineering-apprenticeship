# Lesson 10 — What Is Encapsulation?

Before writing code, let's connect this to what you already learned.

In Topic 1, we had something like:

```java
class Student {
    String name;
    int age;
    double grade;
}
```

And outside the class, we could do:

```java
Student student = new Student();

student.name = "John";
student.age = 20;
student.grade = 85.0;
```

This works.

But there's a problem.

Nothing stops someone from doing:

```java
student.age = -500;
student.grade = 999;
student.name = "";
```

Our `Student` object now contains **invalid state**.

---

## What is encapsulation?

**Encapsulation means keeping an object's data protected inside the class and controlling how that data can be accessed or changed.**

Think of it like a vending machine:

```text
             VENDING MACHINE
        ┌──────────────────────┐
        │  Internal mechanism  │
        │  coins               │
        │  inventory           │
        │  sensors             │
        └──────────────────────┘
                  ▲
                  │
          controlled access
                  │
        ┌──────────────────────┐
        │ buttons / interface  │
        └──────────────────────┘
```

You don't reach inside the machine and directly manipulate its inventory.

Instead, you interact through its **allowed interface**.

Objects can work similarly.

```text
Outside code
     │
     ▼
public methods
     │
     ▼
┌───────────────────┐
│      Student      │
│                   │
│ private name      │
│ private age       │
│ private grade     │
│                   │
│ validation        │
└───────────────────┘
```

The class controls how its internal state changes.

---

# The basic Java pattern

Instead of:

```java
class Student {
    String name;
    int age;
}
```

we can use:

```java
class Student {
    private String name;
    private int age;
}
```

Now code outside `Student` cannot directly do:

```java
student.age = 20;
```

because `age` is **private**.

Instead, the class can provide methods such as:

```java
public void setAge(int age) {
    this.age = age;
}
```

and:

```java
public int getAge() {
    return age;
}
```

We'll study these methods properly in Lessons 13–14.

For now, understand the relationship:

```text
private field
     ↓
protect the data

public method
     ↓
controlled access
```

---

# Why is this useful?

Suppose we want a student's age to always be between 1 and 120.

Without encapsulation:

```java
student.age = -20;
```

The class has no opportunity to stop it.

With encapsulation:

```java
public void setAge(int age) {
    if (age >= 1 && age <= 120) {
        this.age = age;
    }
}
```

Now the class controls the change.

```text
setAge(-20)
     ↓
Is -20 valid?
     ↓
    NO
     ↓
Don't change the object's state
```

This is one of the major ideas behind encapsulation:

> **The object is responsible for protecting its own state.**

---

# 🧠 Important distinction

Encapsulation is **not simply "make everything private."**

The bigger idea is:

> **Hide internal state and provide controlled ways for other code to interact with the object.**

`private` is one of the Java tools we use to achieve that.

## Next concept — `private`

Now let's see how Java prevents that.

```java
class BankAccount {
    private double balance;
}
```

The keyword:

```java
private
```

means that `balance` can only be accessed **from inside the `BankAccount` class**.

So this is allowed:

```java
class BankAccount {
    private double balance;

    void resetBalance() {
        balance = 0; // ✅ inside BankAccount
    }
}
```

But outside the class:

```java
BankAccount account = new BankAccount();

account.balance = 500; // ❌
```

Java will stop us because `balance` is `private`.
