### 🎯 Lesson Goal

Today you'll learn how to let outside code **read or change private fields without giving it direct access**.

The key idea:

```text
private field
      ↓
 getter / setter
      ↓
 outside code
```

---

# 1. The Problem

Suppose we have:

```java
class Student {
    private String name;
    private int age;
}
```

Because they're private, this doesn't work:

```java
student.name = "John";  // ❌
student.age = 20;      // ❌
```

But what if outside code **needs to know the student's name or age**?

We need a controlled way to access them.

That's where **getters** and **setters** come in.

---

# 2. Getter

A **getter** is a method used to retrieve a private field's value.

Example:

```java
class Student {
    private String name;

    String getName() {
        return name;
    }
}
```

Outside code can then do:

```java
Student student = new Student();

System.out.println(student.getName());
```

Notice:

```text
student.name
    ❌ direct access

student.getName()
    ✅ controlled access
```

The getter **gets** the value.

---

# 3. Setter

A **setter** is a method used to change a private field's value.

```java
class Student {
    private String name;

    void setName(String newName) {
        name = newName;
    }
}
```

Outside code:

```java
student.setName("John");
```

The setter **sets** the value.

---

# 4. Why Not Just Make the Field Public?

Compare:

### Public field

```java
class Student {
    public int age;
}
```

Outside:

```java
student.age = -50;
```

The outside code has direct control.

---

### Private field + setter

```java
class Student {
    private int age;

    void setAge(int newAge) {
        age = newAge;
    }
}
```

Now we have a place where we can eventually put rules:

```java
void setAge(int newAge) {

    if (newAge >= 0) {
        age = newAge;
    }
}
```

Now the object controls its own data.

That's the important connection:

```text
Private field
     ↓
Setter
     ↓
Validation / rules
     ↓
Field changes only when allowed
```
