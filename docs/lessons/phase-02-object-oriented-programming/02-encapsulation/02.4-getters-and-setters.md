### 🎯 Lesson Goal

Today you'll learn how to let outside code **read or change private fields without giving it direct access**.

The key idea:

```text
private field
      ↓
 getter / setter
      ↓
 outside code
```

---

# 1. The Problem

Suppose we have:

```java
class Student {
    private String name;
    private int age;
}
```

Because they're private, this doesn't work:

```java
student.name = "John";  // ❌
student.age = 20;      // ❌
```

But what if outside code **needs to know the student's name or age**?

We need a controlled way to access them.

That's where **getters** and **setters** come in.

---

# 2. Getter

A **getter** is a method used to retrieve a private field's value.

Example:

```java
class Student {
    private String name;

    String getName() {
        return name;
    }
}
```

Outside code can then do:

```java
Student student = new Student();

System.out.println(student.getName());
```

Notice:

```text
student.name
    ❌ direct access

student.getName()
    ✅ controlled access
```

The getter **gets** the value.

---

# 3. Setter

A **setter** is a method used to change a private field's value.

```java
class Student {
    private String name;

    void setName(String newName) {
        name = newName;
    }
}
```

Outside code:

```java
student.setName("John");
```

The setter **sets** the value.

---

# 4. Why Not Just Make the Field Public?

Compare:

### Public field

```java
class Student {
    public int age;
}
```

Outside:

```java
student.age = -50;
```

The outside code has direct control.

---

### Private field + setter

```java
class Student {
    private int age;

    void setAge(int newAge) {
        age = newAge;
    }
}
```

Now we have a place where we can eventually put rules:

```java
void setAge(int newAge) {

    if (newAge >= 0) {
        age = newAge;
    }
}
```

Now the object controls its own data.

That's the important connection:

```text
Private field
     ↓
Setter
     ↓
Validation / rules
     ↓
Field changes only when allowed
```

Use:

```java
public class Exercise13A {

    static class Student {
        private String name;

        String getName() {
            return name;
        }

        void setName(String newName) {
            name = newName;
        }
    }

    public static void main(String[] args) {

        Student student = new Student();

        student.setName("John");

        System.out.println(student.getName());
    }
}
```

### Your task

Don't modify the code yet.

Answer these:

**1.** Which method is the **getter**?

**2.** Which method is the **setter**?

**3.** What value is stored in `name` after this runs?

```java
student.setName("John");
```

**4.** What does this return?

```java
student.getName()
```

Answer those four in your own words, then we'll move to **Exercise 13B**.

All 4 are correct. ✅

Let's make the distinction very clear:

```java
student.setName("John");
```

means:

> **Set/change the `name` field to `"John"`.**

So internally:

```text
name = "John"
```

Then:

```java
student.getName()
```

means:

> **Get/return the current value stored in `name`.**

So it returns:

```text
"John"
```

### Remember this pattern

```java
setName("John");   // put/change a value
getName();         // retrieve a value
```

A useful mental shortcut:

```text
SET → PUT
GET → TAKE
```
