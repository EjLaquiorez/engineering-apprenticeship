### 🎯 Lesson Goal

By the end of this lesson, you should understand:

> **Why fields are commonly made `private` and how that protects an object's internal state.**

---

## 1. The Problem With Public Fields

Consider this:

```java
class BankAccount {
    public double balance;
}
```

Outside code can directly change the balance:

```java
BankAccount account = new BankAccount();

account.balance = 1000;
account.balance = -500;
```

The problem is that **nothing prevents invalid changes**.

We might want the rule:

```text
balance must never be negative
```

But with a public field, anyone can bypass that rule.

---

## 2. Making the Field Private

We can protect the field:

```java
class BankAccount {
    private double balance;
}
```

Now this:

```java
account.balance = 1000;
```

will no longer work from outside the `BankAccount` class.

Why?

Because:

```text
private
   ↓
only the declaring class can directly access it
```

So the object itself becomes responsible for controlling its own state.

---

## 3. Think of the Object as a Boundary

Imagine:

```text
Outside Code
     │
     │  ❌ direct access
     ▼
┌──────────────────────────┐
│      BankAccount         │
│                          │
│  private balance 🔒      │
│                          │
│  rules live here         │
└──────────────────────────┘
```

Instead of allowing outside code to manipulate `balance` directly, we can later provide controlled methods such as:

```java
deposit()
withdraw()
```

This is where encapsulation becomes useful:

> **The object protects its own data and controls how that data can change.**

# Exercise 12A — Make the Field Private

Create:

```text
exercises/phase-02-object-oriented-programming/02-encapsulation/Exercise12A.java
```

Start with this:

```java
public class Exercise12A {

    static class BankAccount {
        double balance;
    }

    public static void main(String[] args) {

        BankAccount account = new BankAccount();

        account.balance = 1000;

        System.out.println("Balance: " + account.balance);
    }
}
```

### Your task

Change **only the field declaration** so that `balance` becomes private.

Then try compiling the program.

You should discover that these lines:

```java
account.balance = 1000;
```

and

```java
account.balance
```

cause an access error.

### Your question

Before changing anything else, tell me:

**Why does `account.balance` stop working from `main()` after `balance` becomes `private`?**

Don't worry about fixing the program yet. We want to understand the problem first.
