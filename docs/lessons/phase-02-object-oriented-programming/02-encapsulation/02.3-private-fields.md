### 🎯 Lesson Goal

By the end of this lesson, you should understand:

> **Why fields are commonly made `private` and how that protects an object's internal state.**

---

## 1. The Problem With Public Fields

Consider this:

```java
class BankAccount {
    public double balance;
}
```

Outside code can directly change the balance:

```java
BankAccount account = new BankAccount();

account.balance = 1000;
account.balance = -500;
```

The problem is that **nothing prevents invalid changes**.

We might want the rule:

```text
balance must never be negative
```

But with a public field, anyone can bypass that rule.

---

## 2. Making the Field Private

We can protect the field:

```java
class BankAccount {
    private double balance;
}
```

Now this:

```java
account.balance = 1000;
```

will no longer work from outside the `BankAccount` class.

Why?

Because:

```text
private
   ↓
only the declaring class can directly access it
```

So the object itself becomes responsible for controlling its own state.

---

## 3. Think of the Object as a Boundary

Imagine:

```text
Outside Code
     │
     │  ❌ direct access
     ▼
┌──────────────────────────┐
│      BankAccount         │
│                          │
│  private balance 🔒      │
│                          │
│  rules live here         │
└──────────────────────────┘
```

Instead of allowing outside code to manipulate `balance` directly, we can later provide controlled methods such as:

```java
deposit()
withdraw()
```

This is where encapsulation becomes useful:

> **The object protects its own data and controls how that data can change.**

```java
public class Exercise12A {

    }

```

### Your task

Change **only the field declaration** so that `balance` becomes private.

Then try compiling the program.

You should discover that these lines:

```java
account.balance = 1000;
```

and

```java
account.balance
```

cause an access error.

### Your question

Before changing anything else, tell me:

**Why does `account.balance` stop working from `main()` after `balance` becomes `private`?**

Don't worry about fixing the program yet. We want to understand the problem first.

Exactly. ✅

More precisely:

> `balance` can no longer be accessed directly from `main()` because `balance` is `private`, and `main()` is outside the `BankAccount` class.

Think of the boundary:

```text
main()
  │
  │ ❌ cannot directly access
  ▼
┌──────────────────────┐
│    BankAccount       │
│                      │
│ private balance 🔒   │
│                      │
└──────────────────────┘
```

But here's the important part:

**The field isn't inaccessible to everything.** The `BankAccount` class itself can still access it.

For example, this is allowed:

```java
static class BankAccount {
    private double balance;

    void showBalance() {
        System.out.println(balance);
    }
}
```

Because `showBalance()` belongs to `BankAccount`.

## Exercise 12B — Inside vs. Outside

Now let's test that distinction.

Create:

```text
Exercise12B.java
```

Use this starting code:

```java
public class Exercise12B {

    static class BankAccount {
        private double balance;

        void setBalance() {
            balance = 1000;
        }

        void showBalance() {
            System.out.println("Balance: " + balance);
        }
    }

    public static void main(String[] args) {

        BankAccount account = new BankAccount();

        account.setBalance();
        account.showBalance();
    }
}
```

### Your task

Before running it, answer these two questions:

**1.** Why can `setBalance()` change `balance` even though `balance` is private?

**2.** Why can `main()` call `setBalance()` but cannot do this?

```java
account.balance = 5000;
```

Answer in your own words first.

Correct. ✅

One small refinement:

```java
private double balance;
```

* `balance` → **field**
* `private` → only the `BankAccount` class can directly access it.

```java
void setBalance()
```

* `setBalance()` → **method**
* no modifier → **package-private**
* code in the same package can access it.

So your understanding is:

```text
private balance
→ only inside BankAccount 🔒

void setBalance()
→ accessible outside BankAccount if the code is in the same package
```

### ⭐ Key Encapsulation Idea

This gives us a controlled path:

```text
Outside code
     │
     │ calls method
     ▼
setBalance()
     │
     │ changes
     ▼
private balance 🔒
```

Outside code **doesn't directly control the field**. It goes through the object's method.
