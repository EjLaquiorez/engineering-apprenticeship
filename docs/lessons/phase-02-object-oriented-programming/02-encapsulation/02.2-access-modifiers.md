## 1. What is an access modifier?

You've already used two:

```java
private double balance;

public void withdraw(double amount) {
}
```

The words:

```text
private
public
```

are **access modifiers**.

They control **where something can be accessed from**.

Think of them as doors with different permissions.

```text
Field / Method
      │
      ▼
Access Modifier
      │
      └── Who is allowed to access this?
```

Java has four access levels we'll learn:

```java
public
protected
(no modifier)
private
```

For now, we're going to start with the two you already encountered:

```java
public
private
```

---

# 2. `private`

Consider:

```java
class BankAccount {

    private double balance;

}
```

`balance` belongs to `BankAccount`, and because it's `private`, code inside `BankAccount` can directly use it.

For example:

```java
class BankAccount {

    private double balance;

    void resetBalance() {
        balance = 0; // ✅
    }
}
```

But code outside `BankAccount` cannot directly do:

```java
BankAccount account = new BankAccount();

account.balance = 500; // ❌
```

A good beginner mental model is:

```text
private
   ↓
Only my class can directly access me.
```

---

# 3. `public`

Now consider:

```java
class BankAccount {

    public void deposit(double amount) {
        // ...
    }
}
```

Because `deposit()` is `public`, outside code can call it:

```java
BankAccount account = new BankAccount();

account.deposit(500); // ✅
```

So:

```text
public
   ↓
Other code can access me.
```

This gives us the encapsulation pattern you discovered in Lesson 10:

```java
class BankAccount {

    private double balance;

    public void deposit(double amount) {
        // control how balance changes
    }

    public void withdraw(double amount) {
        // control how balance changes
    }
}
```

The **data is protected**, while selected operations are exposed.

```text
             OUTSIDE CODE
                  │
       ┌──────────┴──────────┐
       │                     │
 deposit(500) ✅       withdraw(200) ✅
       │                     │
       ▼                     ▼
┌─────────────────────────────────┐
│          BankAccount            │
│                                 │
│      private balance 🔒         │
│                                 │
└─────────────────────────────────┘

account.balance ❌
```

### One important distinction

`private` doesn't mean:

> "Nobody can access it."

It means:

> **"Code outside the class cannot directly access it."**

The `Student` class itself can still use `grade`:

```java id="f9gqj5"
class Student {

    private double grade;

    void displayGrade() {
        System.out.println(grade); // ✅
    }
}
```

That's an important distinction to remember.

# Access Modifiers — The Four Levels

Now we're ready to introduce the other two.

Java has:

| Modifier        | Basic idea                                                   |
| --------------- | ------------------------------------------------------------ |
| `public`        | Accessible broadly                                           |
| `protected`     | Accessible within the class/package, plus certain subclasses |
| *(no modifier)* | Accessible within the same package                           |
| `private`       | Accessible only within the declaring class                   |

Don't try to memorize the full `protected` rules yet. We'll build them gradually.

For now, think of access as a **visibility scale**:

```text id="0p1d5c"
More accessible
      ↑
   public
   protected
   package-private
   private
      ↓
Less accessible
```

Where **package-private** means you write **no modifier**:

```java id="m2ub6g"
class Student {

    double grade;   // package-private

}
```

There is no keyword like `package`.

Look at these four fields:

```java id="x5m4u8"

```

Match each one with the description.

**A.** Only the class itself can directly access it.

**B.** Code in the same package can access it; subclasses in other packages can also have access under certain rules.

**C.** Code broadly can access it.

**D.** Code in the same package can access it.

Give me your answer like:

```text
a → ?
b → ?
c → ?
d → ?
```

Take your best guess.


You have the **four concepts**, but the matching got mixed up. That's okay—this is exactly what we're practicing. 👍

Let's correct it:

| Field | Modifier    | Correct meaning                                |
| ----- | ----------- | ---------------------------------------------- |
| `a`   | `public`    | **C** — broadly accessible                     |
| `b`   | `protected` | **B** — same package + certain subclass access |
| `c`   | *(none)*    | **D** — same package                           |
| `d`   | `private`   | **A** — only the declaring class               |

So:

```text
a → C ✅
b → B ✅
c → D ✅
d → A ✅
```

You knew the meanings—you just matched the letters in the wrong direction. 😄

### Let's simplify the mental model

Imagine four doors:

```text
public
   ↓
Almost anyone can enter

protected
   ↓
Package + certain subclasses

package-private
   ↓
Same package

private
   ↓
Only this class
```

The key thing to remember for your current OOP work is:

> **`private` is the main tool we'll use to protect an object's internal state.**
