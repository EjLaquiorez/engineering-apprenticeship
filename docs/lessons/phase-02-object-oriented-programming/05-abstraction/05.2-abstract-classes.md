## Lesson 28A — First concept

An abstract class is a class declared with the `abstract` keyword. It can define shared state and behavior, but Java does not allow you to instantiate it directly.

Consider:

```
abstract class LibraryItem {
    public void displayType() {
        System.out.println("Library item");
    }
}
```

The method `displayType()` already has an implementation. An abstract class does not have to contain only unfinished methods.

Compare these declarations:

```
LibraryItem item;                 // Valid
// LibraryItem item = new LibraryItem(); // Invalid
```

The first declares a reference variable. The second attempts to create an abstract-class object, which Java prohibits.

## 1. Review your understanding

Given this code:

```
abstract class Animal {
}

class Dog extends Animal {
}
```

- `Animal` is abstract, so you cannot create an object directly with `new Animal()`.
- `Dog` is concrete, so you can create an object with `new Dog()`.
- `Dog` inherits from `Animal`, even though you never create an `Animal` object directly.

Remember, a child class can be instantiated only if it fulfills the requirements for a concrete class. In this example, `Animal` has no abstract methods that `Dog` needs to implement.

## 2. The key concept you've learned

In Exercise 28A, the abstract parent supplied a complete method implementation. In Exercise 28B, the abstract parent defined a contract that the child had to fulfill.

An abstract method is useful when every child must provide behavior, but the correct behavior differs by child type.

For example:

- `Book.displayType()` → `"This is a book."`
- `Magazine.displayType()` → `"This is a magazine."`
- `DVD.displayType()` → `"This is a DVD."`

All three classes can follow the same contract while providing different implementations.

## Let's reinforce the rule

| Class declaration                                                                  | Can you instantiate it? | Why?                                                               |
| ---------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------ |
| `abstract class LibraryItem`                                                       | No                      | Abstract classes cannot be instantiated directly.                  |
| `class Book extends LibraryItem` with `displayType()` implemented                  | Yes                     | It fulfills the inherited abstract method requirement.             |
| `class Magazine extends LibraryItem` without implementing `displayType()`          | No, compilation fails   | It hasn't fulfilled the requirement and isn't declared abstract.   |
| `abstract class Magazine extends LibraryItem` without implementing `displayType()` | No                      | It can leave the requirement for a concrete descendant to fulfill. |
