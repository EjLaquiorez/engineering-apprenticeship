## 1. What is an abstract method?

In Lesson 28, you learned that an abstract class can contain a method without a body.

For example:

```
abstract class Animal {
    public abstract void makeSound();
}
```

Look carefully at the method:

```
public abstract void makeSound();
```

Unlike a regular method, it has no braces `{ }` containing instructions. It ends with a semicolon.

This tells Java:

> Every concrete child of `Animal` must provide its own implementation of `makeSound()`.

The parent defines what behavior is required, while each child defines how that behavior works.

## Code review

1\. Abstract method — correct

```
public abstract void makeSound();
```

You declared the method without a body. `Animal` specifies the required behavior but leaves its implementation to subclasses.

2\. Method overriding — correct

Both `Dog` and `Cat` use `@Override` and provide their own method bodies. This fulfills the contract established by `Animal`.

3\. Object creation — correct

```
Dog dog = new Dog();
Cat cat = new Cat();
```

Both classes are concrete, so you can instantiate them.

4\. Method calls — correct

```
dog.makeSound();
cat.makeSound();
```

Each call executes the implementation belonging to the actual object.

## One important concept to remember

You cannot instantiate the abstract parent directly:

```
Animal animal = new Animal(); // Compilation error
```

But you can use an `Animal` reference to refer to a concrete child object:

```
Animal animal = new Dog();
animal.makeSound(); // Prints Woof!
```

This works because `Dog` is a concrete subclass of `Animal`. The reference type determines which methods are available through the variable, while runtime method dispatch selects the overridden implementation.

Before coding, consider this scenario:

An abstract `Payment` class declares an abstract method named `processPayment()`. Two concrete subclasses, `CashPayment` and `CardPayment`, extend `Payment`.

Question: What must each subclass do to be concrete, and why?

Explain it in your own words first. I'll check your understanding before we move into the coding task.

Correct! Your understanding is on the right track. You identified the two important parts: inherit the abstract method and implement it in each subclass.

Let's make your explanation a little more precise.

- `CashPayment` inherits the abstract method `processPayment()` from `Payment` and provides its own implementation.
- `CardPayment` also inherits `processPayment()` and provides its own implementation.
- Each subclass can implement the method differently to match its payment type.

For example, cash payment might print `"Processing cash payment."`, while card payment might print `"Processing card payment."`.

Why is this necessary? Because both subclasses are concrete classes. A concrete class must implement all inherited abstract methods unless it is itself declared abstract.
