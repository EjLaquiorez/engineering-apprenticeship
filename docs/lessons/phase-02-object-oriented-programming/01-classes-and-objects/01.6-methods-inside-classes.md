# Part 1 — The Big Idea

So far, we've learned that an object can contain **data**.

For example:

```java
class Dog {
    String name;
    int age;
}
```

A `Dog` object can have:

```text
name = "Buddy"
age  = 3
```

But an object shouldn't just **store information**.

It can also **do something**.

For example:

```text
Dog

Data:
    name
    age

Behavior:
    bark
    eat
    sleep
```

This gives us an important OOP idea:

> **Fields represent what an object has. Methods represent what an object can do.**

---

# Part 2 — What Is an Instance Method?

You already learned methods in Phase 01.

For example:

```java
static void greet() {
    System.out.println("Hello");
}
```

That method belongs to the **class**, rather than a particular object.

Now we can put a method **inside a class** that operates on an individual object.

Example:

```java
class Dog {
    String name;

    void bark() {
        System.out.println("Woof!");
    }
}
```

Notice something important:

```java
void bark()
```

doesn't have `static`.

That makes it an **instance method**.

It belongs to an object created from the class.

---

# Part 3 — Calling the Method

Suppose we create a Dog:

```java
Dog dog = new Dog();
```

We can call its method using:

```java
dog.bark();
```

Think about the dot:

```text
dog.bark()
 ↑    ↑
 │    └── method
 │
 └────── object
```

You're basically saying:

> "Hey, `dog`, perform your `bark` behavior."

# Part 4 — Fields + Methods

Here's where OOP starts becoming more interesting.

```java
class Dog {
    String name;

    void bark() {
        System.out.println(name + " says Woof!");
    }
}
```

Then:

```java
Dog dog = new Dog();
dog.name = "Buddy";

dog.bark();
```

The output is:

```text
Buddy says Woof!
```

Why can `bark()` access `name`?

Because the method belongs to the **same object**.

Conceptually:

```text
dog
 │
 ↓
┌─────────────────┐
│ Dog object      │
│                 │
│ name = "Buddy"  │
│                 │
│ bark()          │
└─────────────────┘
```

The object's **state** and **behavior** are together.

That's one of the fundamental ideas behind OOP.

---

# Part 5 — Compare This With Phase 01

In procedural programming, you might have:

```java
String name = "Buddy";

static void bark(String name) {
    System.out.println(name + " says Woof!");
}
```

You have to pass the data into the method.

With an instance method:

```java
class Dog {
    String name;

    void bark() {
        System.out.println(name + " says Woof!");
    }
}
```

The object already owns the data.

So:

```java
dog.bark();
```

doesn't need:

```java
dog.bark(dog.name);
```

The method can work with the object's own state.
