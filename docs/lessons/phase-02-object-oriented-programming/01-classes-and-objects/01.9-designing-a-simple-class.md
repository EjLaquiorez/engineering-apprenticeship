### Main idea

We've learned how to create classes, objects, fields, methods, constructors, references, and overloaded constructors.

Now we need to answer a more important question:

> **How do we decide what belongs inside a class?**

For example, imagine a `Student` class.

A student might have:

```text
name
age
grade
```

Those make sense as **fields** because they describe the student's state.

Possible behaviors:

```text
displayInfo()
study()
```

Those make sense as **methods** because they describe what the student can do.

But something like:

```text
calculatePizzaPrice()
```

doesn't naturally belong to `Student`.

That's the beginning of **class design**.

### First understanding question

Suppose we're designing a `BankAccount` class.

Which of these would make sense as **fields**?

```text
balance
deposit()
accountNumber
withdraw()
ownerName
displayBalance()
```

Pick the fields and explain why.



These are fields:

```text
balance
accountNumber
ownerName
```

because they describe the **state/information that a BankAccount object has**.

The others:

```text
deposit()
withdraw()
displayBalance()
```

are methods because they describe **behavior/actions the object can perform**.

### Mental model

```text
BankAccount
├── Fields → what it has
│   ├── balance
│   ├── accountNumber
│   └── ownerName
│
└── Methods → what it does
    ├── deposit()
    ├── withdraw()
    └── displayBalance()
```

This is the same pattern you've been practicing:

> **Fields = what the object has**
> **Methods = what the object does**

## Lesson 09 — Understanding Check 2

Now suppose we have:

```java
class Student {
    String name;
    int age;
    double grade;

    void displayInfo() {
        System.out.println(name);
        System.out.println(age);
        System.out.println(grade);
    }

    void study() {
        System.out.println(name + " is studying.");
    }
}
```

Why does `displayInfo()` belong inside the `Student` class instead of putting it in a completely unrelated class?

Explain it in your own words.
