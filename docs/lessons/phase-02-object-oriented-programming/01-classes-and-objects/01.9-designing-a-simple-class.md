### Main idea

We've learned how to create classes, objects, fields, methods, constructors, references, and overloaded constructors.

Now we need to answer a more important question:

> **How do we decide what belongs inside a class?**

For example, imagine a `Student` class.

A student might have:

```text
name
age
grade
```

Those make sense as **fields** because they describe the student's state.

Possible behaviors:

```text
displayInfo()
study()
```

Those make sense as **methods** because they describe what the student can do.

But something like:

```text
calculatePizzaPrice()
```

doesn't naturally belong to `Student`.

That's the beginning of **class design**.

### First understanding question

Suppose we're designing a `BankAccount` class.

Which of these would make sense as **fields**?

```text
balance
deposit()
accountNumber
withdraw()
ownerName
displayBalance()
```

Pick the fields and explain why.
