# Topic 1 — Classes & Objects

### Lesson 02 — What Is a Class?

**Goal:** Understand a class as the blueprint used to create objects.

Before I explain it, let's test your intuition.

Imagine we're building a `Car` program.

We want every car to potentially have:

```text
brand
color
speed

start()
accelerate()
brake()
stop()
```

Now imagine we need **three cars**:

```text
Toyota
Honda
Ford
```

### Question

Would it make sense to write a completely separate definition of `brand`, `color`, `speed`, `start()`, `accelerate()`, etc. for every single car?

Or would it be better to create **one blueprint** describing what a Car has and does, then create individual cars from that blueprint?

**Tell me which approach you think makes more sense and why.**


The **second approach** is what OOP gives us.

Think of a **class as a blueprint**.

For example:

```text
             CAR BLUEPRINT
                  │
        ┌─────────┴─────────┐
        │                   │
     Toyota              Honda
        │                   │
   brand = Toyota      brand = Honda
   color = Red        color = Blue
```

Both cars follow the same general structure because they come from the same **`Car` class**, but each individual car can have different values.

One small correction to your wording:

> "the only thing changes is how they look"

Not necessarily. Their **data/values** can differ too.

For example:

```text
Toyota
brand = Toyota
color = Red
speed = 100

Honda
brand = Honda
color = Blue
speed = 80
```

They share the same **structure and behaviors**, but their individual data can be different.

# Lesson 02 — First Class

Now let's see what that blueprint looks like in Java.

```java
public class Car {

}
```

This is a **class** named `Car`.

Right now it's an empty blueprint.

We can eventually put the Car's data and behavior inside it:

```java
public class Car {

    String brand;
    String color;
    int speed;

    void start() {
        System.out.println("Car started");
    }
}
```

Don't worry about understanding every piece yet.

For now, notice the structure:

```text
Car
│
├── brand
├── color
├── speed
│
└── start()
```

The class describes what a `Car` **has** and what a `Car` **can do**.

## Exercise 02 — Read the Class

Look at this:

```java
public class Student {

    String name;
    int age;
    double grade;

    void study() {
        System.out.println("Student is studying");
    }

    void displayInformation() {
        System.out.println(name);
        System.out.println(age);
        System.out.println(grade);
    }
}
```

Answer these **without writing code yet**:

1. What is the name of the class?
2. What are the three pieces of **data**?
3. What are the two **behaviors**?
4. In your own words, what is the purpose of this `Student` class?
5. Is `Student` itself a particular student, or is it a blueprint for students?

Take your time. After this, we'll introduce the really important distinction between a **class** and an **object**.
