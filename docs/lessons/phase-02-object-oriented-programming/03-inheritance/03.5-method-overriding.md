# Part 1 — What Does "Override" Mean?

Imagine the parent says:

> "Every animal can make a sound."

So we create:

```java
class Animal {
    public void makeSound() {
        System.out.println("Animal makes a sound.");
    }
}
```

Then we create:

```java
class Dog extends Animal {
}
```

Because `Dog extends Animal`, the Dog inherits `makeSound()`.

So:

```java
Dog dog = new Dog();
dog.makeSound();
```

uses the parent's method.

But perhaps we want a Dog to make a more specific sound.

We can write:

```java
class Dog extends Animal {
    public void makeSound() {
        System.out.println("Dog barks.");
    }
}
```

Now `Dog` has its **own version** of `makeSound()`.

That is **method overriding**.

---

## Think of it this way

### Without overriding

```text
Animal
 └── makeSound()
       "Animal makes a sound."

Dog
 └── inherits makeSound()
```

### With overriding

```text
Animal
 └── makeSound()
       "Animal makes a sound."

Dog
 └── makeSound()
       "Dog barks."
```

The child is saying:

> "I inherited this behavior, but I have a more specific way to perform it."

# Exercise 20A — Override a Method

Before you code, answer this:

Suppose we have:

```java
class Animal {
    public void move() {
        System.out.println("Animal is moving.");
    }
}

class Dog extends Animal {
    public void move() {
        System.out.println("Dog is running.");
    }
}
```

And:

```java
Dog dog = new Dog();
dog.move();
```

### Question:

Which message will print?

**A.**

```text
Animal is moving.
```

**B.**

```text
Dog is running.
```

**C. Both messages**

Choose **A, B, or C**, and explain **why** in your own words.
