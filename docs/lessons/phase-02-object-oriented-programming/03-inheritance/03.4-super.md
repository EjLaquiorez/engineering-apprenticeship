# 1. What is `super`?

You already know:

```java
class Dog extends Animal
```

This means:

```text
Animal
   ↑
  Dog
```

`Dog` is the child, and `Animal` is the parent.

Inside `Dog`, the keyword:

```java
super
```

means:

> **"The parent portion of this object."**

So if you're inside `Dog`:

```java
super
```

refers to the `Animal` side.

---

# 2. `super(...)` calls the parent constructor

Look at your previous code:

```java
static class Animal {
    private final String name;
    private final int age;

    Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

And:

```java
static class Dog extends Animal {

    Dog(String name, int age, String breed) {
        super(name, age);
        this.breed = breed;
    }
}
```

When you do:

```java
Dog dog = new Dog("Buddy", 3, "Labrador");
```

the flow is roughly:

```text id="0o4z5x"
new Dog(...)
     ↓
Dog constructor
     ↓
super("Buddy", 3)
     ↓
Animal constructor
     ↓
Animal initializes name + age
     ↓
back to Dog constructor
     ↓
Dog initializes breed
```

So:

```java id="l6x3kf"
super(name, age);
```

means:

> "Call the constructor of my parent class and give it these arguments."

### Important rule

Just like `this(...)`, a constructor call using `super(...)` must be the **first statement** in the constructor.

---

# 3. `this(...)` vs `super(...)`

This is especially important because you learned `this(...)` in Topic 1.

### `this(...)`

Calls **another constructor in the same class**.

```java id="g2kn5q"
Book(String title, String author) {
    this(title, 0, author);
}
```

Meaning:

```text
Book constructor
     ↓
another Book constructor
```

### `super(...)`

Calls a constructor in the **parent class**.

```java id="5h3b4n"
Dog(String name, int age) {
    super(name, age);
}
```

Meaning:

```text
Dog constructor
     ↓
Animal constructor
```

Remember:

```text id="f5t9kw"
this(...)  → another constructor in THIS class
super(...) → constructor in the PARENT class
```

### Why it is correct

Your parent constructor expects:

```java
Animal(String name, int age)
```

Your child constructor receives:

```java
Dog(String name, int age, String breed)
```

So the parent should receive only the data that **belongs to the parent**:

```java
super(name, age);
```

Then `Dog` handles its own data:

```java
this.breed = breed;
```

The flow is:

```text id="2x6w4s"
new Dog("Doggy", 3, "Labradog")
        │
        ▼
Dog constructor
        │
        ├── super("Doggy", 3)
        │       │
        │       ▼
        │   Animal constructor
        │       ├── name = "Doggy"
        │       └── age = 3
        │
        └── this.breed = "Labradog"
```

That's the exact purpose of `super(...)`.

# Exercise 19B — Access Parent Behavior

Now we'll use the **second major use of `super`**.

So far:

```java
super(...)
```

calls a **parent constructor**.

But `super` can also call a **parent method**.

Imagine:

```java
static class Animal {
    public void eat() {
        System.out.println("Animal is eating.");
    }
}
```

and:

```java
static class Dog extends Animal {
    public void eat() {
        super.eat();
        System.out.println("Dog is eating.");
    }
}
```

Inside `Dog`:

```java
super.eat();
```

means:

> **Call the `eat()` method defined in the parent class.**

So the output would be:

```text
Animal is eating.
Dog is eating.
```

We'll study *why* a child might want to do this more deeply with overriding in Lesson 20.
