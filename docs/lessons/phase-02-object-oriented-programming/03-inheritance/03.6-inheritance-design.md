# Part 1 — The Most Important Inheritance Question

Before creating:

```java
class Dog extends Animal
```

you should ask:

> **Is a Dog actually an Animal?**

Yes.

```text
Dog IS-A Animal
```

That's an appropriate inheritance relationship.

But consider:

```java
class Engine extends Car
```

Is an engine a car?

❌ No.

A car **has an engine**.

So this is a **has-a** relationship:

```text
Car
 └── has an Engine
```

Not:

```text
Car
 └── extends Engine ❌
```

---

# Is-a vs Has-a

### Is-a → inheritance

```text
Dog IS-A Animal
Cat IS-A Animal
Manager IS-A Employee
Developer IS-A Employee
```

Usually represented with:

```java
class Dog extends Animal
```

---

### Has-a → composition

```text
Car HAS-A Engine
Library HAS-A Book
Student HAS-A Address
Computer HAS-A Keyboard
```

Usually represented by putting an object inside another class:

```java
class Car {
    private Engine engine;
}
```

Notice:

```text
Car
 └── engine
       ↓
     Engine
```

The `Car` **contains/references** an `Engine`.

It doesn't inherit from it.

---

# Why does this matter?

Inheritance creates a relationship between classes.

If you write:

```java
class Dog extends Animal
```

you're saying:

> A Dog is a specialized kind of Animal.

That creates a strong connection between the two classes.

You shouldn't use inheritance simply because:

> "I can reuse some code from this class."

Code reuse is useful, but **the relationship must make sense first**.

# Exercise 21B — Design Decision

Now let's make the decision as a Java developer.

Suppose we have:

```text
Vehicle
├── Car
└── Motorcycle
```

A Car **is a** Vehicle.

A Motorcycle **is a** Vehicle.

So inheritance makes sense:

```java
class Car extends Vehicle
class Motorcycle extends Vehicle
```

Now consider:

```text
Car
└── Engine
```

A Car **has an** Engine.

So we would **not** write:

```java
class Car extends Engine   // ❌
```

Instead:

```java
class Car {
    private Engine engine;
}
```
