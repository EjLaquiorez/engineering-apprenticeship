# 1. Why do we create a parent class?

Look at these two classes:

```text
Dog
- name
- age
- eat()
- sleep()
- bark()

Cat
- name
- age
- eat()
- sleep()
- meow()
```

If we don't use inheritance, we'd have to repeat:

```java
String name;
int age;

void eat() { ... }

void sleep() { ... }
```

in both classes.

But `name`, `age`, `eat()`, and `sleep()` aren't really unique to dogs or cats.

They are **common to animals**.

So we can move them into:

```text
        Animal
       /      \
     Dog      Cat
```

Now:

```text
Animal
├── name
├── age
├── eat()
└── sleep()

Dog
└── bark()

Cat
└── meow()
```

This is one of the major purposes of a parent class:

> **Put genuinely common data and behavior in one place so child classes can reuse it.**

---

# 2. Common data vs child-specific data

Let's take `Dog` and `Cat`.

### Common data

Both have:

```text
name
age
```

So these can belong to `Animal`.

### Dog-specific data

Suppose a dog has:

```text
breed
```

That doesn't necessarily belong in `Animal`.

A cat doesn't have a dog breed.

So:

```text
Animal
├── name
└── age

Dog
└── breed
```

Likewise, if `Cat` has:

```text
furColor
```

that could belong specifically to `Cat`.

The basic rule is:

> **If every child naturally needs it, consider putting it in the parent.**

> **If only one type needs it, keep it in that child.**

# Exercise 17C — Shared Behavior

Now let's focus specifically on **behavior**.

We have:

```text
Dog
- bark()
- eat()
- sleep()

Cat
- meow()
- eat()
- sleep()

Bird
- fly()
- eat()
- sleep()
```

### Your task

Imagine you are designing the parent class `Animal`.

Answer these two questions:

**1.** Should `eat()` be in `Animal` or only in each child? **Why?**

**2.** Should `bark()` be in `Animal` or only in `Dog`? **Why?**

Don't code yet. I want you to explain the design decision in your own words.

Exactly. ✅ Both answers show you understand the purpose of a parent class.

### 1. `eat()` → `Animal`

Your reasoning:

> "All animals eat."

Correct. Since `Dog`, `Cat`, and `Bird` all share this behavior, it belongs in the parent:

```text id="9l8z7f"
Animal
└── eat()
```

Then every child inherits it.

---

### 2. `bark()` → `Dog`

Your reasoning:

> "Dog only barks."

Correct. `bark()` is **specific behavior**, so it belongs in `Dog`:

```text id="5p7q0d"
Animal
├── eat()
└── sleep()

Dog
└── bark()

Cat
└── meow()

Bird
└── fly()
```

This gives us an important design rule:

> **Common behavior → parent.**
> **Specialized behavior → child.**

### What you should now be able to recognize

Given several related classes, you should be able to ask:

```text
1. What data do they all share?
        ↓
   Put it in parent

2. What behavior do they all share?
        ↓
   Put it in parent

3. What is unique to one child?
        ↓
   Keep it in that child
```

That's the foundation for designing an inheritance hierarchy.
