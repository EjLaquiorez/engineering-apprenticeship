# 1. Linux vs Windows

Linux and Windows are both operating systems, but they expose the system to engineers in different ways.

### Windows

Windows commonly uses:

```text
C:\
├── Users\
├── Program Files\
├── Windows\
└── ...
```

PowerShell and Command Prompt are commonly used to interact with the system.

Example:

```powershell
Get-ChildItem
Get-Location
Set-Location
```

### Linux

Linux uses a single filesystem tree beginning at:

```text
/
```

Example:

```text
/
├── home
├── etc
├── usr
├── var
├── tmp
└── ...
```

A Linux shell commonly provides commands such as:

```bash
pwd
ls
cd
mkdir
cp
mv
rm
```

### Engineering perspective

The important difference is not simply:

> "Linux has different commands."

The deeper difference is that Linux exposes many operating-system concepts through the filesystem, processes, permissions, devices, configuration files, and command-line tools.

For software engineers, Linux becomes important because many servers, containers, CI systems, cloud environments, and development environments run Linux.

# 2. Linux Filesystem Hierarchy

Linux starts at the root directory:

```text
/
```

Everything exists somewhere below `/`.

Important directories include:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── opt
├── proc
├── root
├── run
├── sbin
├── tmp
├── usr
└── var
```

## `/home`

Contains normal users' home directories.

Example:

```text
/home/justine
```

Your personal files normally live here.

---

## `/root`

The home directory of the root user.

This is different from:

```text
/
```

`/` is the filesystem root.

`/root` is the root user's home directory.

---

## `/etc`

Contains system configuration.

Examples:

```text
/etc/hosts
/etc/passwd
/etc/ssh/
```

Think:

> `/etc` = system configuration.

---

## `/var`

Contains data that changes while the system operates.

Examples include:

```text
/var/log
/var/cache
/var/lib
```

Think:

> `/var` = variable/runtime data.

---

## `/tmp`

Temporary files.

Applications may use this directory for temporary data.

---

## `/usr`

Contains many user-space programs, libraries, and other resources.

For example:

```text
/usr/bin
/usr/lib
/usr/share
```

---

## `/dev`

Represents devices exposed to the operating system.

Examples may include:

```text
/dev/null
/dev/sda
```

---

## `/proc`

A virtual filesystem containing information about processes and the running kernel.

For example:

```text
/proc/cpuinfo
/proc/meminfo
```

This demonstrates an important Linux concept:

> Some things that look like files are interfaces to operating-system information.

# 3. Paths and Navigation

A **path** identifies the location of something in the filesystem.

There are two major types.

## Absolute path

An absolute path starts from `/`.

Example:

```bash
/home/justine/projects
```

It describes the complete location.

---

## Relative path

A relative path starts from your current directory.

Example:

```bash
projects/app
```

Its meaning depends on where you currently are.

---

## Current directory

Linux represents the current directory as:

```text
.
```

Example:

```bash
./script.sh
```

---

## Parent directory

The parent directory is represented by:

```text
..
```

Example:

```bash
cd ..
```

This moves one directory upward.

# 4. pwd, ls, and cd

These are fundamental navigation commands.

## `pwd`

Print working directory.

```bash
pwd
```

Example:

```text
/home/justine/projects
```

Engineering interpretation:

> "Where am I?"

---

## `ls`

Lists directory contents.

```bash
ls
```

Useful forms:

```bash
ls -l
ls -a
ls -la
```

### `-l`

Long format.

```bash
ls -l
```

Shows information such as:

- permissions
- owner
- group
- size
- modification time
- filename

### `-a`

Includes hidden files.

Linux hidden files commonly begin with:

```text
.
```

Example:

```text
.gitignore
.bashrc
```

---

## `cd`

Change directory.

```bash
cd /home/justine
```

Go to the parent:

```bash
cd ..
```

Go home:

```bash
cd ~
```

Return to the previous directory:

```bash
cd -
```

# 5. Creating and Managing Files and Directories

## Create a directory

```bash
mkdir project
```

Create nested directories:

```bash
mkdir -p project/src/main
```

---

## Create an empty file

```bash
touch app.txt
```

---

## Copy

```bash
cp source.txt destination.txt
```

Copy a directory recursively:

```bash
cp -r source destination
```

---

## Move

```bash
mv old.txt new.txt
```

`mv` can also move files:

```bash
mv app.txt project/
```

---

## Remove a file

```bash
rm app.txt
```

Remove an empty directory:

```bash
rmdir directory
```

Remove a directory recursively:

```bash
rm -r directory
```

Be careful with:

```bash
rm -rf
```

It can remove files recursively without interactive confirmation.

Engineering rule:

> Treat destructive commands as irreversible until proven otherwise.

Before deleting something, inspect it.

```bash
pwd
ls
```

## `less`

Useful for logs and large output.

# 7. Wildcards and Pattern Matching

Wildcards allow commands to work with groups of filenames.

## `*`

Matches zero or more characters.

Example:

```bash
ls *.txt
```

Matches:

```text
a.txt
notes.txt
report.txt
```

---

## `?`

Matches one character.

```bash
ls file?.txt
```

Could match:

```text
file1.txt
file2.txt
```

but not:

```text
file10.txt
```

---

## Character ranges

```bash
file[1-5].txt
```

Can match:

```text
file1.txt
file2.txt
file3.txt
file4.txt
file5.txt
```

Wildcards become especially powerful when combined with commands such as:

```bash
ls
cp
mv
rm
grep
```

# 8. Pipes and Redirection

One of the most important Linux concepts is connecting commands together.

## Standard output

Normally:

```bash
ls
```

prints output to the terminal.

---

## Redirect output with `>`

```bash
ls > files.txt
```

Instead of displaying the output, it writes it to `files.txt`.

Important:

```bash
>
```

overwrites the destination.

---

## Append with `>>`

```bash
ls >> files.txt
```

This adds output to the end of the file.

---

## Pipe with `|`

A pipe sends the output of one command into another command.

Example:

```bash
ls | grep ".txt"
```

Conceptually:

```text
ls
 ↓
output
 ↓
grep
 ↓
filtered output
```

This is a major engineering pattern:

> Build small tools that perform one operation and combine them.

---

## Error redirection

Standard error can be redirected:

```bash
command 2> errors.txt
```

Both standard output and standard error can be combined:

```bash
command > output.txt 2>&1
```

`grep` searches text.

Basic example:

```bash
grep "ERROR" application.log
```

This searches for lines containing:

```text
ERROR
```

---

## Case-insensitive search

```bash
grep -i "error" application.log
```

---

## Show line numbers

```bash
grep -n "ERROR" application.log
```

---

## Recursive search

```bash
grep -r "TODO" .
```

Searches recursively from the current directory.

---

## Combine with pipes

```bash
ps aux | grep java
```

This creates a pipeline:

```text
ps
 ↓
process list
 ↓
grep
 ↓
lines containing java
```

`find` searches the filesystem.

Example:

```bash
find . -name "*.java"
```

This searches the current directory and descendants for Java files.

---

## Find directories

```bash
find . -type d
```

---

## Find files

```bash
find . -type f
```

---

## Find by name

```bash

```

---

## Find and execute an action

Example:

```bash

```

Be extremely careful with destructive operations.

A safer first step is:

```bash
find . -name "*.tmp"
```

Inspect the result before deleting anything.

# 11. File Permissions

Linux controls access using permissions.

A typical permission string might look like:

```text
-rwxr-xr--
```

It can be divided into:

```text
- rwx r-x r--
  │   │   │
  │   │   └── others
  │   └────── group
  └────────── owner
```

The permissions are:

```text
r = read
w = write
x = execute
```

---

## Example

```text
-rwxr-xr--
```

Means:

### Owner

```text
rwx
```

Can read, write, execute.

### Group

```text
r-x
```

Can read and execute.

### Others

```text
r--
```

Can only read.

---

## chmod

Change permissions:

```bash
chmod +x script.sh
```

This adds execute permission.

Numeric permissions are also common:

```bash
chmod 755 script.sh
```

The values represent:

```text
read    = 4
write   = 2
execute = 1
```

Therefore:

```text
7 = 4 + 2 + 1 = rwx
5 = 4 + 1     = r-x
```

So:

```text
755
```

means:

```text
owner:  rwx
group:  r-x
others: r-x
```

# 12. Users and Groups

Linux is a multi-user operating system.

Files have an owner and group.

Example:

```bash
ls -l
```

Might show:

```text
-rw-r--r-- 1 justine developers 1200 app.java
```

The important parts include:

```text
owner: justine
group: developers
```

This creates a security model:

```text
user
 ↓
group
 ↓
permissions
 ↓
resource access
```

---

## Current user

```bash
whoami
```

---

## User identity

```bash
id
```

This can show:

- user ID
- group ID
- groups

---

## Changing ownership

Administrative privileges may be required:

```bash
chown user file.txt
```

Change owner and group:

```bash
chown user:group file.txt
```

# 13. Processes

A process is a running instance of a program.

For example:

```text
Java application
       ↓
    process
       ↓
     PID
```

PID means:

> Process ID.

---

## View processes

```bash
ps
```

More detailed:

```bash
ps aux
```

---

## Search processes

```bash
ps aux | grep java
```

---

## `top`

```bash
top
```

Shows running processes and resource usage interactively.

---

## Terminate a process

```bash
kill PID
```

Example:

```bash
kill 1234
```

A stronger signal may be used when appropriate:

```bash
kill -9 1234
```

Do not treat `kill -9` as the default solution.

Engineering approach:

1. Identify the process.
2. Understand what it is doing.
3. Attempt graceful termination.
4. Force termination only when necessary.

View a variable:

echo $HOME

Example:

```text
/home/justine
```

Another common variable:

```bash
echo $USER
```

List environment variables:

```bash
env
```

or:

```bash
printenv
```

---

## Temporary variable

```bash
export APP_ENV=development
```

Then:

```bash
echo $APP_ENV
```

Output:

```text
development
```

Environment variables are commonly used for:

- configuration
- credentials
- runtime settings
- application modes
- paths

# 15. PATH

`PATH` is one of the most important environment variables for engineers.

View it:

```bash
echo $PATH
```

It contains directories separated by `:`.

Example:

```text
/usr/local/bin:/usr/bin:/bin
```

When you execute:

```bash
java
```

the shell searches directories in `PATH` to find the executable.

Conceptually:

```text
java
 ↓
search PATH
 ↓
/usr/local/bin/java
 ↓
execute
```

---

## Why PATH matters

Suppose you install a tool but receive:

```text
command not found
```

Possible causes include:

- the program isn't installed
- the executable isn't where expected
- the directory isn't in `PATH`
- the shell has stale configuration

You can locate commands with:

```bash
which java
```

or:

```bash
command -v java
```

# 17. Shell Basics

The shell is a program that interprets commands.

Examples include:

```text
bash
zsh
fish
```

The shell receives commands and executes programs.

For example:

```bash
ls
```

Conceptually:

```text
User
 ↓
Shell
 ↓
Program
 ↓
Operating System
 ↓
Result
```

---

## Command structure

A command commonly looks like:

```bash
command options arguments
```

Example:

```bash

```

Breaking it down:

```text
command   = ls
option    = -la
argument  = /var/log
```

## Command history

Many shells support:

```text
↑
```

to retrieve previous commands.

You can also use:

```bash

```

---

## Help

Most Linux commands provide help.

Examples:

```bash

```

and:

```bash

```

A shell script is a file containing shell commands.

Example:

```bash

```

Save it as:

```text

```

```bash

```

Run it:

```bash
./setup.sh
```

---

## Variables

```bash
NAME="Justine"

```

---

## Arguments

A script can receive arguments.

```bash
echo "First argument: $1"
```

Run:

```bash
./script.sh hello
```

Then:

```text
$1
```

contains:

```text
hello
```

---

## Conditions

Example:

```bash
if [ -f "app.txt" ]; then
    echo "File exists"
else
    echo "File does not exist"
fi
```

---

## Loops

Example:

```bash
for file in *.txt; do
    echo "$file"
done
```

# 19. Exit Codes and Error Handling

Linux commands return an exit status.

Conventionally:

```text
0 = success
non-zero = failure/error condition
```

Example:

```bash
ls
echo $?
```

If successful:

```text
0
```

---

## Why exit codes matter

A script can use the exit code to determine whether an operation succeeded.

Example:

```bash
if command; then
    echo "Command succeeded"
else
    echo "Command failed"
fi
```

This is fundamental to:

- shell scripts
- CI/CD pipelines
- build systems
- automation
- deployment systems

---

## Fail-fast scripting

A commonly used Bash option is:

```bash
set -e
```

This tells Bash to exit when certain commands fail.

More robust scripts may also use:

```bash
set -euo pipefail
```

Each option changes error behavior and should be understood before using it blindly.

# 20. Linux Troubleshooting Workflow

Linux troubleshooting should be systematic rather than based on random commands.

A useful engineering workflow is:

```text
1. Observe
   ↓
2. Reproduce
   ↓
3. Gather evidence
   ↓
4. Form a hypothesis
   ↓
5. Test the hypothesis
   ↓
6. Apply the smallest safe change
   ↓
7. Verify
   ↓
8. Document
```

---

## Step 1 — Observe

Start with the actual symptom.

Example:

```text
Application won't start.
```

Don't immediately modify configuration.

---

## Step 2 — Reproduce

Try to reproduce the problem.

For example:

```bash
./start.sh
```

Observe the exact error.

---

## Step 3 — Gather evidence

Useful commands may include:

```bash
pwd
ls -la
ps aux
env
echo $PATH
df -h
free -h
```

For logs:

```bash
tail -f application.log
```

---

## Step 4 — Form a hypothesis

Example:

> "The application probably cannot find Java because `java` isn't available through PATH."

Test it:

```bash
java -version
```

Then:

```bash
command -v java
```

Then:

```bash
echo $PATH
```

---

## Step 5 — Test

Don't change five things at once.

Change one relevant thing and test again.

This preserves cause-and-effect information.

---

## Step 6 — Apply the smallest safe change

Avoid unnecessary system-wide modifications.

For example, if an application only needs a temporary environment variable:

```bash
export APP_ENV=development
```

may be preferable to immediately changing global configuration.

---

## Step 7 — Verify

After making a change:

```bash
./start.sh
```

Then verify the application actually works.

Don't stop at:

```text
No error appeared.
```

Verify the intended behavior.

---

## Step 8 — Document

Record:

```text
Problem
Cause
Evidence
Fix
Verification
```

This turns troubleshooting into reusable engineering knowledge.

# Engineering Mental Model

The goal of Linux fundamentals is not to memorize dozens of commands.

The important mental model is:

```text
                    Linux
                      │
       ┌──────────────┼──────────────┐
       │              │              │
   Filesystem      Processes      Users
       │              │              │
       │              │              │
   Paths/files     PIDs/state     Permissions
       │              │              │
       └──────────────┼──────────────┘
                      │
                    Shell
                      │
              Commands/scripts
                      │
                Applications
```

These concepts interact constantly.

For example, when an application fails:

```text
Application
     ↓
Process
     ↓
User
     ↓
Permissions
     ↓
Environment variables
     ↓
PATH
     ↓
Filesystem
     ↓
Configuration
     ↓
Logs
```

Understanding those relationships is much more valuable than simply remembering commands.
