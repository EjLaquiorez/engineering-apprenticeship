# Step 4 — Understand What VS Code Is Doing

When you open:

```text
engineering-apprenticeship/
```

VS Code isn't replacing Git.

Git still operates independently:

```text
             VS Code
                │
       ┌────────┼────────┐
       ↓        ↓        ↓
      Java     Git    Terminal
       │        │        │
       └────────┼────────┘
                ↓
             Project
```

The important distinction is:

> **VS Code provides an interface for development tools; it does not replace those tools.**

For example, when you click **Commit** in VS Code, VS Code is interacting with Git.

# Step 7 — The Important IDE Mental Model

This is what I want you to understand:

```text
VS Code
│
├── Editor
│     └── Write Java
│
├── Integrated Terminal
│     └── Run commands
│
├── Source Control
│     └── Work with Git
│
├── Java tooling
│     └── Compile/debug/test
│
├── Maven tooling
│     └── Manage Maven projects
│
└── Gradle tooling
      └── Manage Gradle projects
```

The IDE brings these capabilities together.

But underneath:

```text
Java → javac/java
Git → git
Maven → mvn
Gradle → gradle/gradlew
```

are still separate tools.

That's an important professional concept.
