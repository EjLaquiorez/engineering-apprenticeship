# 2. Listing Files and Directories

## `Get-ChildItem`

```powershell
Get-ChildItem
```

Lists the contents of the current directory.

Common aliases:

```powershell
dir
ls
gci
```

Example:

```powershell
Get-ChildItem
```

Output contains properties such as:

- `Mode`
- `LastWriteTime`
- `Length`
- `Name`

---

## Wildcards

### `*`

```powershell
Get-ChildItem *
```

`*` is a wildcard that broadly matches items.

### `*.txt`

```powershell
Get-ChildItem *.txt
```

Matches files whose names end in `.txt`.

Example:

```text
notes.txt
```

### `-Filter`

```powershell
Get-ChildItem -Filter *.txt
```

Filters the results to `.txt` files.

Important distinction:

```text
*             → broad wildcard
*.txt         → specific wildcard pattern
-Filter *.txt → explicit filtering parameter
```

# 3. Creating, Moving, Copying, Renaming, and Removing Items

## `New-Item`

Creates a new item.

Example:

```powershell
New-Item notes.txt
```

For a file:

```powershell
New-Item log.txt -ItemType File
```

For a directory:

```powershell
New-Item archive -ItemType Directory
```

---

## `Move-Item`

Moves an item to another location.

Example:

```powershell
Move-Item notes-copy.txt archive
```

This moves:

```text
notes-copy.txt
```

into:

```text
archive\
```

The original location no longer contains the item.

---

## `Copy-Item`

Copies an item while leaving the original in place.

Example:

```powershell
Copy-Item notes.txt notes-copy.txt
```

---

## `Remove-Item`

Removes an item.

Example:

```powershell
Remove-Item archive\notes-copy.txt
```

To remove an empty directory:

```powershell
Remove-Item archive
```

---

## `Rename-Item`

Renames an item.

Example:

```powershell
Rename-Item -Path "old.txt" -NewName "new.txt"
```

Conceptually:

```text
-Path    → where the original item is
-NewName → what the item should be called
```

---

# 4. Reading File Content

## `Get-Content`

Reads the contents of a file.

```powershell
Get-Content notes.txt
```

If the file doesn't exist:

```powershell
Get-Content does-not-exist.txt
```

PowerShell reports an error such as:

```text
Cannot find path ... because it does not exist.
```

`Get-Content` works with **file content**.

This is different from `Get-Item`, which retrieves the **item/object itself**.

---

## `Get-Item`

```powershell
Get-Item notes.txt
```

Retrieves the file as an object.

That allows access to properties such as:

```powershell
(Get-Item notes.txt).Length
```

The `Get-Item` part identifies the object whose property we want to inspect.

## `Get-Command`

# 8. Wildcards, Filtering, and Object Pipelines

PowerShell pipelines connect commands:

```powershell
Get-ChildItem | Where-Object ...
```

The pipe:

```text
|
```

passes the output objects from one command into the next command.

---

## `Where-Object`

Filters objects.

Example:

```powershell
Get-ChildItem |
    Where-Object Length -gt 100
```

Means:

> Get the items, then keep only objects whose `Length` is greater than 100.

Example result:

```text
error.txt
listing.txt
```

---

## `Sort-Object`

Sorts objects by a property.

Example:

```powershell
Get-ChildItem *.txt |
    Sort-Object Length -Descending
```

`-Descending` means largest values appear first.

---

## `Select-Object`

Selects properties or limits results.

Example:

```powershell
Get-ChildItem *.txt |
    Sort-Object Length -Descending |
    Select-Object -First 1 Name, Length
```

This means:

1. Get `.txt` files.
2. Sort by size, largest first.
3. Take the first result.
4. Display only `Name` and `Length`.

Because the largest file is first, `-First 1` finds the largest file.

---

# 9. Counting Results

A pipeline can be used to determine how many objects are returned.

Example concept:

```powershell
Get-ChildItem *.txt
```

retrieves the `.txt` files.

The result can then be counted.

The important idea is:

```text
Get objects
    ↓
Count objects
```

# 10. Redirection

PowerShell can redirect command output into files.

## `>`

```powershell
Get-ChildItem > listing.txt
```

Creates or **replaces** the contents of `listing.txt`.

## `>>`

```powershell
Get-ChildItem >> listing.txt
```

Creates or **appends** to `listing.txt`.

The key difference:

```text
>   → create/replace
>>  → append
```

---

# 11. Redirecting Errors

PowerShell uses numbered streams.

Error output is stream `2`.

Example:

```powershell
Get-Content does-not-exist.txt 2> error.txt
```

This redirects the error output into:

```text
error.txt
```

Then:

```powershell
Get-Content error.txt
```

shows the captured error.

The concept is:

```text
Command
   ↓
Error stream (2)
   ↓
2> error.txt
   ↓
error.txt
```

# 12. Exit / Success Status with `$?`

PowerShell provides `$?` to indicate whether the previous command succeeded.

Successful command:

```powershell
Get-ChildItem
$?
```

Result:

```text
True
```

Failed command:

```powershell
Get-Content does-not-exist.txt
$?
```

Result:

```text
False
```

Conceptually:

```text
True  → previous command succeeded
False → previous command failed
```

# 13. Objects and Properties

One of the most important PowerShell concepts is that commands commonly produce **objects**, not merely text.

For example:

```powershell
Get-ChildItem
```

produces filesystem objects with properties such as:

```text
Name
Length
LastWriteTime
Mode
```

This allows:

```powershell
Get-ChildItem |
    Where-Object Length -gt 100
```

because `Where-Object` can inspect the `Length` property of each object.

# 14. `ForEach-Object` and `$_`

`ForEach-Object` processes objects one at a time.

Example:

```powershell
Get-ChildItem *.txt |
    ForEach-Object {
        "File: $($_.Name)"
    }
```

Output:

```text
File: error.txt
File: listing.txt
File: notes.txt
```

Inside the script block:

```powershell
$_
```

means:

> The current object being processed.

Example:

```powershell
$($_.Name)
```

means:

> Get the `Name` property from the current object.

---

## Calculating values with `ForEach-Object`

Example:

```powershell
Get-ChildItem *.txt |
    ForEach-Object {
        "$($_.Name) is $($_.Length) bytes"
    }
```

This produced output such as:

```text
error.txt is 982 bytes
listing.txt is 1146 bytes
notes.txt is 25 bytes
```

We then transformed bytes to kilobytes:

```powershell
Get-ChildItem *.txt |
    ForEach-Object {
        "$($_.Name): $($_.Length / 1024) KB"
    }
```

This demonstrates:

```text
raw object data
    ↓
process each object
    ↓
calculate a new value
    ↓
produce human-readable output
```

# 15. `Select-Object` vs `ForEach-Object`

A key distinction:

### `Select-Object`

Used to select or shape properties.

```powershell
Get-Process notepad |
    Select-Object ProcessName, Id
```

Think:

```text
Select-Object → select/shape information
```

### `ForEach-Object`

Used to process or transform each object.

```powershell
Get-Process notepad |
    ForEach-Object {
        "$($_.ProcessName) has PID $($_.Id)"
    }
```

Think:

```text
ForEach-Object → do something with each object
```

# 17. Comparisons

PowerShell uses comparison operators.

Common operators:

```text
-eq  → equal
-ne  → not equal
-gt  → greater than
-ge  → greater than or equal
-lt  → less than
-le  → less than or equal
```

Examples:

```powershell
$size -gt 20
```

Result:

```text
True
```

```powershell
$size -eq 25
```

Result:

```text
True
```

```powershell
$size -gt 100
```

Result:

```text
False
```

```powershell
$size -lt 100
```

Result:

```text
True
```

It can return multiple processes because several PowerShell sessions can exist simultaneously.

```powershell
Get-Process python
```


```text
Installed program
```

and:

```text
Currently running process
```

# 24. Process IDs (PID)

Every running process has a Process ID.

Example:

```text
ProcessName → notepad
PID         → 7204
```

The PID identifies a specific running instance.

This distinction is important:

```text
Process name → identifies the program
PID           → identifies a specific running instance
```

If multiple instances of the same program are running, they can have the same process name but different PIDs.

---

# 25. Inspecting a Specific Process

Use:

```powershell
Get-Process -Id 6600
```

to retrieve a specific process by PID.

Then:

```powershell
Get-Process -Id 6600 |
    Select-Object Id, ProcessName, CPU, WorkingSet
```

can display selected properties.

Example:

```text
Id          → 6600
ProcessName → notepad
CPU         → 0.109375
WorkingSet  → 14905344
```

# 26. Stopping a Process

```powershell
Stop-Process -Id 6600
```


```text

   ↓
```

# 27. Filtering Processes

The same `Where-Object` concept used with files works with processes.

Example:

```powershell
Get-Process |
    Where-Object ProcessName -eq "notepad"
```

Meaning:

> Get all processes, then keep only objects whose `ProcessName` equals `notepad`.

The pipeline is:

```text
Get-Process
    ↓
all process objects
    ↓
Where-Object
    ↓
only Notepad objects
```

# 30. Calculated Properties

You created a calculated property to convert memory from bytes to megabytes:

```powershell
Get-Process |
    Sort-Object WorkingSet -Descending |
    Select-Object -First 5 ProcessName, Id,
        @{Name="MemoryMB"; Expression={[math]::Round($_.WorkingSet / 1MB, 2)}}
```

The result was easier to read:

```text
ProcessName           Id MemoryMB
-----------           -- --------
brave              16220   426.32
Memory Compression  2672   391
Cursor             15240   385.75
MsMpEng             5204   360.5
```

The calculated property:

```powershell
@{
    Name="MemoryMB"
    Expression={[math]::Round($_.WorkingSet / 1MB, 2)}
}
```

means:

```text
Name
 ↓
Name the output column MemoryMB

Expression
 ↓
Calculate the value

$_.WorkingSet
 ↓
WorkingSet of the current object

/ 1MB
 ↓
Convert bytes to MB

[Math]::Round(..., 2)
 ↓
Round to two decimal places
```
